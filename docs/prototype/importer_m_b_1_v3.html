Step 1 · Source (Simple mode).
  • Toggle переключён в «Простой». Stepper показывает один шаг «drop → ready» — нет Step 2.
  • После drop файла: parse → sanitize → addLibraryEntry({autoAnnotate: false}) → toast «pUC19 добавлен в Library» → Importer закрывается автоматически. Биолог моментально возвращается в DAG.
  • Auto-annotate выключен — биолог получает features из самого файла (если .gb/.dna), либо нулевые annotations (если .fasta). Это «голый сек» о котором ты писал.
  • Multi-file в Simple: все файлы параллельно (Promise.all на parseFile), один toast «3 файла добавлены». Никаких per-file controls, dedup решается autoname'ом silently.
  • В footer не «Далее →», а текст «после drop — Importer закроется автоматически» — биолог понимает что не будет диалогов.
Биология-аргумент. Casual user / batch workflow «просмотреть 10 файлов от коллабораторов»: в SnapGene 1 click double-click → instant view. Simple mode — flash success state.
  • Это transient state: показывается на ~1 секунду после успешного импорта Простым режимом, потом Importer auto-close.
  • Animation pipeline: file dropped → parsed → sanitized → saved → DAG node — все done с timing. Биолог видит что произошло.
  • Footer кнопки: «Открыть в Container Window» (escape hatch если хочется проверить что получилось), «Импортировать ещё» (cancel auto-close, остаться в Importer).
  • Multi-file simple — single flash показывает «3 файла добавлены» с разъединённым списком имён.
  • Rationale: silent auto-close — это что биолог хочет в casual flow («drop, done, back to work»), но flash на 1 sec даёт visual ack «ничего не сломалось, всё сохранилось». Без flash биолог думает «а реально импортировалось?» и открывает Library проверять.

Step 2 · Combined view (Advanced mode, упрощённый).
  • Sequence pane read-only (badge сверху). Нельзя править sequence. Биолог видит цветную подсветку annotations + AA-strip — для review «то ли это что я думал». Правки sequence — после Confirm через Container Window M-D с ContainerCommit (author + timestamp + history).
  • BLAST panel removed из M-B.1. Biology rationale: BLAST = exploration mode, биолог редко делает это в момент import (он ещё не знает что странное). Перенесён в M-D Container Window после первого месяца usage.
  • Auto-annotate checkbox добавлен в left column (между map и annotations) — биолог может dynamically выключить enrichment и увидеть «голые» features из файла. Эквивалент Простого режима для текущего файла. Default ON.
  • Annotation editing остаётся (legitimate use-case: правка имени feature, удаление мусорной разметки legacy файла).
  • Origin rotation остаётся (legitimate: pUC19 conventions для published structure).
  • Cross-pane sync (click annotation → подсветка в sequence) остаётся для read-only.
v3 delta vs v2. Удалено: BLAST gaps panel (~150 px высоты), sequence editing toolbar (Substitute/Insert/Select/Find→Replace), edit cursor, edit-status badge. Добавлено: «read-only» badge в sequence toolbar, «Auto-annotate» checkbox в left column. Combined view simpler, но keeps essential review affordances.

Modal · Primer wizard (unified pool).
  • Один action: «Add to primer pool» — праймеры идут в единый pool с metadata (project + status + origin). Никаких opt-in checkbox'ов «также в проектный pool».
  • Status chips per-primer: imported (из файла), designed (auto-design в Mix), ordered / received (биолог промотит вручную). Разные цвета.
  • Дубль (resourceHash совпадает с existing primer в pool) — warning row + chip «⚠ дубль» вместо unchecked. Биолог может явно check'нуть → autoname как контейнеры (M13 Forward (1)).
  • В Простом режиме primer-step не показывается. Primers либо игнорируются (default), либо silently импортируются с status=imported (опц. в settings).
  • Никакого DEC-IMP-11 strict separation. Library Primers tab = primer pool filter «orphan» (project=null или archived). Project pool = filter «current project». Один store, два view.
v3 delta vs v2. Footnote v2 «Library only, NOT project pool» → unified pool с metadata. Биолог не должен ручную копировать primer из Library в project pool (friction в casual flow). Промотирование status (imported→ordered→received) делается в M-F primer pool view (см. следующий таб «Primer pool view»).
