# Система документации BodgeGene / PlasmidVCS

## Проблема

Три агента работают над проектом:
1. **Claude Chat** — проектирование, аудит, спецификации
2. **Claude Code** — реализация кода
3. **Игорь** — тестирование, утверждение, координация

Каждый теряет контекст между сессиями. Документация — единственный способ передать контекст.

---

## Решение: иерархия документов

```
Уровень 1 — Точка входа (всегда читать первым):
  CLAUDE.md                 ← ЧТО: архитектура, правила, структура

Уровень 2 — Динамическое состояние:
  PROJECT_STATE.md          ← ГДЕ МЫ: модули, баги, журнал сессий
  CURRENT_TASK.md           ← ЧТО ДЕЛАТЬ: задание с инструкциями
  DECISIONS.md              ← ПОЧЕМУ: решения (append-only)

Уровень 3 — Детальные спецификации:
  docs/INDEX.md             ← Мастер-индекс всех документов
  docs/ARCHITECTURE_v2.md   ← Модель данных
  docs/ASSEMBLY_ENGINE_v2.md← Сборка + праймеры
  docs/PART_MODEL.md        ← Наследование Part
  ...                       ← (см. docs/INDEX.md)

Уровень 4 — Справочные:
  CHANGELOG.md              ← История версий
  TEST_RESULTS.md           ← Результаты аудита
  PALETTE_SPEC.md           ← UI спецификация
```

## Правила обновления

### Кто обновляет что

| Файл | Кто обновляет | Когда |
|------|--------------|-------|
| CLAUDE.md | Claude Code / Chat | При изменении структуры или правил (~1 раз в неделю) |
| PROJECT_STATE.md | Claude Code | **После каждой сессии** (журнал + статусы) |
| CURRENT_TASK.md | Claude Chat | Перед каждой задачей; Claude Code отмечает done |
| DECISIONS.md | Claude Chat / Code | При принятии архитектурного решения |
| CHANGELOG.md | Claude Code | При релизе новой версии |
| docs/INDEX.md | Claude Code | При добавлении/удалении документов |
| docs/*.md | Claude Chat | При проектировании новых модулей |

### Что обновлять после рабочей сессии Claude Code

1. **PROJECT_STATE.md:**
   - Добавить запись в "Журнал сессий" (дата, что сделано, коммиты)
   - Обновить статусы модулей (если изменились)
   - Обновить статусы багов (если исправлены)
   - Обновить метрики (строки кода, количество тестов)

2. **CURRENT_TASK.md:**
   - Отметить выполненные задачи
   - Добавить новые задачи (если обнаружены в процессе)

3. **DECISIONS.md** (если были приняты архитектурные решения):
   - Добавить запись: `[ДАТА] **Решение.** Обоснование.`

## Восстановление контекста

```
Прочитай CLAUDE.md, PROJECT_STATE.md и CURRENT_TASK.md из C:\Users\Zoman\Desktop\RESplasmide
```

### Claude Chat (новый чат)
```
Прочитай PROJECT_STATE.md и DECISIONS.md из репо. Затем обсудим следующие шаги.
```

### Глубокое погружение (новый разработчик / сложная задача)
```
Прочитай CLAUDE.md → PROJECT_STATE.md → CURRENT_TASK.md → docs/INDEX.md
Затем читай конкретные docs/ файлы по необходимости.
```

## Workflow

```
Стандартный цикл разработки:

1. Игорь открывает Claude Chat
2. Claude Chat читает PROJECT_STATE.md → понимает где мы
3. Обсуждение → принятие решений → DECISIONS.md
4. Claude Chat пишет CURRENT_TASK.md
5. Игорь говорит Claude Code: "прочитай CLAUDE.md, PROJECT_STATE.md, CURRENT_TASK.md"
6. Claude Code выполняет задачу
7. Claude Code обновляет PROJECT_STATE.md + CURRENT_TASK.md
8. Claude Code: npx vite build && npx vitest run
9. Игорь тестирует визуально
10. При необходимости → скриншоты в Claude Chat → итерация
```

## Принципы

- **Документ = источник правды.** Если в коде одно, а в документе другое — обновить документ.
- **Append-only для решений.** DECISIONS.md не редактируется ретроспективно. Новое решение отменяет старое, но старое остаётся для истории.
- **Минимальный набор для контекста = 3 файла.** CLAUDE.md + PROJECT_STATE.md + CURRENT_TASK.md достаточно для любой задачи.
- **docs/ = глубина.** Детальные спеки читаются только при работе с конкретным модулем, не каждый раз.
