# V106 — Несогласованный перехват хоткеев

## §1 Контекст / корень (подтверждено `hotkeys.js`)

`runHotkeyResolver` (`lib/hotkeys.js`) для каждого hotkey-id проверяет совпадение, scope, и **`if (!_handlers.has(id)) continue`** — id без зарегистрированного хендлера пропускается БЕЗ `preventDefault`. То есть hotkey «работает» только если смонтированный компонент зарегистрировал хендлер через `useHotkey(id, handler)`; иначе срабатывает браузерный дефолт.

- `Ctrl+R` в окне выбора фрагмента «работает», т.к. PCR/assembly-shell регистрирует `pcr-primer-forward` (`useAssemblyPrimerWriting` → `useHotkey('pcr-primer-forward', …)`).
- `Ctrl+F` на канвасе **не перехвачен**: hotkey-id `sequence-search` существует (`scope:'global'`, `allowInInput:true`), но на канвасе CanvasSkeleton его хендлер никто не регистрирует (он регистрируется компонентом sequence-поиска, не канвас-поиском библиотеки) → резолвер пропускает id → срабатывает браузерный find-in-page. Строку поиска канваса биолог открывает мышью.

Предсказуемости нет: одни поверхности регистрируют хендлеры, другие — нет. Потери данных нет (низкий severity).

## §2 Стратегия

(1) Discovery: Code составляет короткую таблицу покрытия — какой hotkey-id каким компонентом регистрируется, какие поверхности имеют поиск/действие без хоткея. (2) Концретный фикс: канвас-поиск (поле «Поиск в библиотеке» на канвасе CanvasSkeleton) регистрирует хендлер для find-хоткея → `Ctrl+F` открывает строку поиска канваса И гасит браузерный find (резолвер `preventDefault`-ит только при наличии хендлера).

## §3 Scope IN
- Discovery-таблица покрытия hotkey-id ↔ регистрирующий компонент (короткий артефакт в отчёт).
- Канвас-поиск регистрирует `useHotkey(<id>, openSearchHandler)` — `Ctrl+F` на канвасе открывает строку поиска.
- Тест: смонтирован канвас → хендлер для find-id зарегистрирован.

## §3 Scope OUT
- `runHotkeyResolver` / реестр `HOTKEYS` рантайм — не переписывать (механизм корректен).
- Глобальная реформа хоткеев — нет; только конкретный gap (Ctrl+F канвас) + видимость через таблицу.

## §4 Открытый вопрос (нужно решение)
- **Какой hotkey-id у канвас-поиска.** `sequence-search` (Ctrl+F) семантически про поиск ПСО в открытой плазмиде — переиспользовать его для поиска библиотечных entry на канвасе — натяжка. Варианты: (а) переиспользовать `sequence-search` (поведение «Ctrl+F = найти» консистентно по приложению, но id назван неточно); (б) новый id `canvas-search`. Рекомендация — (а): для биолога `Ctrl+F` = «найти на текущем экране», единый жест важнее точности имени id. Решает Игорь — без решения батч можно отдать с (а) как дефолтом, поправить тривиально.

# V108 — Счётчик «Контейнеры · N» в редакторе сборки не сходится

## §5 Контекст / корень (подтверждено §F)

`AssemblySidebar` получает `containers={state.containers||[]}` и показывает в header'е `· N` = число контейнеров в `state.containers` с непустым `sequence` (header «Контейнеры · N» добавлен фиксом V95). `state.containers` — **глобальный пул контейнеров скелета**, не scoped ни на зону, ни на сегменты этой сборки, ни на ноды канваса. Пул растёт на каждой вставке сегмента из entry (`AssemblyShellBody.onRangeConfirm` → `addContainerFromEntry`, +1 без дедупа) и на realise (+3). Счётчик и не может «сойтись» с тем, что биолог видит как сборку.

## §6 Стратегия

Не пересчёт — счётчик считает по построению то, что биолог не отслеживает. Честный лейбл: **убрать численный `· N` из header'а** панели (тело панели уже показывает список — это плоский drag-source). Заголовок остаётся («Контейнеры»), `× close` и collapsible-body (V95) сохраняются. Альтернатива — оставить N, но title-tooltip явно «все контейнеры скелета (источник для drag)»; рекомендация — убрать N, tooltip оставить пояснительным.

## §7 Scope IN
- `AssemblySidebar.jsx` — убрать `· N` из header-лейбла (≤5 строк диффа). Заголовок / collapsible / close — не трогать.
- Обновить/снять тест, ассертящий конкретное число в header'е (если есть среди `sidebar-compact-v95`).

## §7 Scope OUT
- Дедуп `addContainerFromEntry` (материализует копию контейнера на каждую вставку из entry) — **сопутствующий настоящий баг**, смыкается с V52 и реестром 8 дублей. НЕ в этом scope — отдельный продуктовый вопрос. В этом батче только косметика счётчика.
- `state.containers` модель / `onRangeConfirm` — не трогать.
