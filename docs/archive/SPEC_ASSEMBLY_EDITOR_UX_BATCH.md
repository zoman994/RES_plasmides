# WT-UX-14 — «Tm» показывается для фрагмент-размерных выделений

## §1 Контекст / корень (подтверждено `RangePickerModal.jsx`)

`RangePickerModal` передаёт `SequenceTab` проп `showSelectionTm` **безусловно**. Tm-ридаут выделения рендерится для любого выделения (код показа — внутри `SequenceTab`/`SequenceView`, с внутренним порогом ~150 п.о.). Tm физически осмысленна только для олигонуклеотидов праймерного размера (~18–50 нт): для фрагмента 150–1500 п.о. число «Tm 77°» биолог в overlap-PCR может прочитать как «отжиг норм», хотя к выбору фрагмента это отношения не имеет.

## §2 Фикс

`RangePickerModal` гейтит `showSelectionTm` по длине выделения: `showSelectionTm={(end - start) <= PRIMER_MAX_LEN}` (константа ~60 нт). Tm-ридаут показывается только для праймер-размерных выделений; для фрагмент-размерных — скрыт. Локальная правка в `RangePickerModal` (`end`/`start` уже вычислены в компоненте). `SequenceTab`/`SequenceView` Tm-механизм НЕ трогаем.

Альтернатива (если Игорь хочет Tm всегда видимой): подписать ридаут «Tm участка» — но это правка в `SequenceTab`/`SequenceView`, шире scope. Рекомендация — гейт по длине (§2 основной), он локален и однозначен.

# WT-UX-15 — лейбл «метод» в селекторе фрагмента вводит в заблуждение

## §3 Контекст / корень (подтверждено `RangePickerModal.jsx`)

Футер-хинт: `` `${end - start} bp выбрано · метод: ${acquisitionMethod}` ``. `acquisitionMethod` = `cursor` / `feature` / `numeric` / `restriction` — это способ ВЫДЕЛЕНИЯ диапазона, а «метод» читается как способ ДОБЫЧИ (PCR / рестрикция). Сама отложенность способа добычи — модель верная (для overlap-PCR праймер зависит от соседнего куска); проблема **только в лейбле**.

## §4 Фикс

Переписать хинт так, чтобы он называл способ ВЫДЕЛЕНИЯ, не «метод». Вариант: `` `${end - start} bp · выделено: {курсором|по фиче|по координатам|по RE-сайтам}` `` — маппинг `acquisitionMethod`→русская формулировка способа выделения. Слово «метод» убрать. Строки — `STRINGS` (namespace по месту). Чисто презентационная правка хинт-строки.

# WT-UX-18 — авто-праймеры не помечены как черновик; нет предупреждения о низкой Tm

## §5 Контекст / корень (подтверждено `AssemblyPrimersPanel.jsx` + `primer-derive.js`)

`deriveAutoPrimers` берёт binding фиксированно 20 нт (`BINDING_LEN`), длину под целевую Tm не подгоняет — AT-богатый конец даёт ~48° (вне рабочего диапазона ПЦР ~55–65°). Докстринг `primer-derive.js` сам помечает это placeholder'ом (доводка — редактор праймера K13), но в UX это нигде не отражено. `AssemblyPrimersPanel.PrimerRow` показывает `autoMode`-бейдж (🔧 «Auto (пересчитывается)» / 🔒 manual) и `Tm {p.tm}°` — но 🔧 не читается биологом как «черновик, доведи руками», и низкая Tm ничем не выделена. Биолог видит 4 готовых праймера с Tm и может уйти в синтез.

## §6 Фикс

`PrimerRow` (`AssemblyPrimersPanel.jsx`), две правки display, независимы от раскола (улучшают показ любого `autoMode:'auto'` / любого низкого `tm`):
1. **Auto = черновик.** Бейдж/тултип для `autoMode==='auto'` усилить: читаться как «черновик — доведите в редакторе праймера», не нейтральное «Auto (пересчитывается)». Текст/иконку — по дизайн-системе панели; tooltip явный.
2. **Предупреждение о Tm вне диапазона.** Когда `p.tm` ниже рабочего порога (константа, ~52°) — рядом с `Tm {p.tm}°` показать ⚠ с тултипом «Tm {x}° вне рабочего диапазона ПЦР (~55–65°) — перепишите праймер вручную». Зеркалит существующий паттерн `status==='stale'` ⚠ в том же `PrimerRow`.

## §7 Где задача сядет / Scope

- **`RangePickerModal.jsx`** — WT-UX-14 (условный `showSelectionTm`), WT-UX-15 (хинт-строка). Локально, других связей нет.
- **`AssemblyPrimersPanel.jsx`** — WT-UX-18 (`PrimerRow` бейдж + Tm-warning). Локально.
- `SequenceTab` / `SequenceView` — НЕ трогать (Tm-механизм; WT-UX-14 решается гейтом пропа на стороне `RangePickerModal`).
- `primer-derive.js` — НЕ трогать (binding-длина 20 нт — сознательный placeholder; подгонка длины под Tm — отдельная задача, не этот батч).
- `selectBoundaryCoverage` / вкладка «Границы» — НЕ трогать (WT-UX-16/17 → Bin 2).

## Scope OUT
- Подгонка длины binding под целевую Tm в `deriveAutoPrimers` — отдельная задача (улучшение алгоритма, не UX-флаг).
- «Tm участка»-релейбл внутри `SequenceTab` — альтернатива WT-UX-14, не основной путь.

## §8 Тесты

- `RangePickerModal`: выделение праймер-размера (≤ порог) → `SequenceTab` получает `showSelectionTm` truthy; фрагмент-размерное (> порог) → falsy.
- `RangePickerModal`: футер-хинт не содержит слова «метод»; для cursor-выделения показывает формулировку способа выделения.
- `AssemblyPrimersPanel`: `PrimerRow` с `autoMode:'auto'` несёт «черновик»-семантику бейджа; с `tm` ниже порога — ⚠-индикатор; с `tm` в норме — без ⚠.
- Регрессия: существующие `RangePickerModal` / `AssemblyPrimersPanel` тесты зелёные.

## §11 Риски

- **R1 — `showSelectionTm` не чисто-булев гейт показа Tm.** Митигация: имя пропа однозначно; если `SequenceTab` интерпретирует иначе — Code сверяет и при необходимости поднимает WT-UX-14 в спеку по `SequenceView` (тогда вынести из батча).
- **R2 — порог рабочей Tm (~52°) спорен.** Митигация: константа в одном месте `PrimerRow`; Игорь тюнит тривиально. Дефолт консервативный — предупреждать только при явно низкой Tm.
- **R3 — WT-UX-18 бейдж не появится, если auto-праймеры не доходят до этой панели.** Митигация: правка корректна для любого `autoMode:'auto'`-праймера в панели; полнота показа auto-праймеров — вопрос раскола (Bin 2), не этого батча.
