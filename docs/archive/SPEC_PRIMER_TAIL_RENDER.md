## §1 Контекст / корень (подтверждено чтением кода)

`deriveAutoPrimers` (`primer-derive.js`) для `kind:'overlap_pcr'` корректно строит overlap-хвост: `buildFwdTail`/`buildRevTail` возвращают `pieceSequence(сосед).slice(±OVERLAP_LEN)` (25 нт). `makePrimer` кладёт `tail` и `sequence = tail+binding`. `op.kind` — действительно `'overlap_pcr'` (панель «Схема сборки» рисует `KIND_LABEL[op.kind]` = «Overlap PCR»). **Хвост существует в данных праймера.** Подтверждено Игорём: полная заказная последовательность `asm-fwd-2` ≈ 45 нт (25 хвост + 20 binding).

Баг — в визуализации, в двух местах:

1. **`useAssemblyPrimerWriting.js` → `viewerPrimers`** (массив, передаваемый в `PrimerTrack`) мапит запись праймера в `{ name, sequence, bindingSequence, direction, tmBinding, crossesBoundaries }` — **поле `tail` отброшено**. До трека хвост не доходит.

2. **`PrimerTrack.jsx`** — `findHits` ищет в шаблоне `p.bindingSequence` и рисует стрелку **только над binding-областью** (`W = (visEnd−visStart)·charPx`). Слово `tail` в файле не встречается — компонент **не знает про overlap-хвост** и не способен его нарисовать.

Итог: два внутренних праймера overlap-PCR (`asm-rev-1` сегмента 1, `asm-fwd-2` сегмента 2) рисуются как 20-нт стрелки над своими binding-областями; binding seg1-rev и binding seg2-fwd сходятся ровно на границе сегментов → биолог видит стык без хвоста, хотя хвост в данных есть.

## §2 Стратегия

Хвост — это 5′-overhang праймера: он НЕ комплементарен этому фрагменту (он матчит соседний). Поэтому рисуется как продолжение стрелки за binding-частью, **не выровненное по шаблонным основаниям**, отдельным стилем (binding = «сидит на матрице», tail = «свисает»). После фикса два внутренних праймера визуально перекроются через границу сегментов — что и есть смысл overlap PCR.

Два шага: (1) пробросить `tail` через `viewerPrimers`; (2) научить `PrimerTrack` рисовать хвост. Изменение в `PrimerTrack` — чисто аддитивное: рендер хвоста гейтится на непустой `hit.tail`; праймеры без `tail` (терминальные auto-праймеры, праймеры из других потребителей трека) не затрагиваются.

## §3 Scope

### Scope IN
- `useAssemblyPrimerWriting.js` — добавить `tail` в объект `viewerPrimers`.
- `PrimerTrack.jsx` — рисовать overlap-хвост как 5′-overhang при непустом `hit.tail`.

### Scope OUT

- Overlap-Tm (Tm самого хвоста / стыка) — отдельная тема (WT-UX-17), не здесь. Лейбл праймера по-прежнему показывает Tm binding-области (`tmBinding`).
- Другие потребители `PrimerTrack` (Library-инспектор и пр.) — аддитивность §2 их не задевает; если их праймеры без `tail` — рендер хвоста просто не включается.
- `selectBoundaryCoverage` / вкладка «Границы» — не относится к этому багу (она и так считает покрытие верно — «1/1 покрыты»).

## §4 Изменения по файлам

### 4.1 `useAssemblyPrimerWriting.js` — проброс `tail`
В `viewerPrimers` (`primers.map(...)`) добавить в возвращаемый объект `tail: p.tail`. Одна строка. После этого `findHits` в `PrimerTrack` получит `tail` на каждом hit через существующий spread `{...p}`.

### 4.2 `PrimerTrack.jsx` — рендер overlap-хвоста
`findHits` / `clipHit` — правок не требуют: `hit` уже несёт `tail` через `{...p}` / `{...h}`.

В рендер-цикле (`lineHits.map`), когда `hit.tail` — непустая строка, дополнительно к binding-стрелке рисуется **сегмент хвоста**:
- Ширина хвоста `tailW = hit.tail.length · charPx`.
- **Forward-праймер:** хвост примыкает к 5′-концу binding-стрелки (локальный `x=0`) и тянется влево: `x ∈ [−tailW, 0]`. Без острия (остриё — на 3′-конце binding).
- **Reverse-праймер:** хвост примыкает к 5′-концу (локальный `x=W`) и тянется вправо: `x ∈ [W, W+tailW]`.
- **Отдельный стиль** от binding-стрелки — хвост не выровнен по матрице: outline / более светлая заливка / штриховка (точный стиль — §10 Q1, по дизайн-системе). Отдельный `<rect>`/`<path>`, не часть `arrowPath`.
- **Основания хвоста:** вписываются из `hit.tail` (НЕ из `upper.slice` — в шаблоне на этих колонках других оснований нет), grid-aligned, под тем же zoom-гейтом `showLetters` (`charPx >= 5`). Ориентация символов хвоста — по той же конвенции, что у binding-оснований для этой цепи.
- **Клик/выделение:** прозрачный hit-target rect и selection-halo расширяются так, чтобы покрывать и хвост (клик по хвосту = выбор праймера).
- **Клиппинг:** хвост у края строки обрезается как binding (частичный рендер допустим).

## §5 Тесты

- `viewerPrimers` (`useAssemblyPrimerWriting`) — для записи праймера с `tail` маппинг содержит `tail`; для записи без `tail` — поле `undefined`, не падает.
- `PrimerTrack` — праймер с непустым `tail`: помимо binding-стрелки рендерится сегмент хвоста (`tailW` колонок) с правильной стороны (forward — слева, reverse — справа от binding).
- `PrimerTrack` — праймер с `tail:''` либо без поля `tail` (терминальный auto-праймер, праймер другого потребителя) — сегмент хвоста НЕ рендерится, поведение как было.
- `PrimerTrack` — клик по области хвоста выбирает праймер (hit-target покрывает хвост).
- Регрессия: существующие тесты `PrimerTrack` (binding-стрелка, V102 wrap-bridge) зелёные; полный Vitest + `vite build`.

## §9 Риски

- **R1 — V102 wrap-bridge: хвост пересекает ▶1 divider.** На bridge-строке хвост, продолжающий binding у origin, может уходить за разделитель. Митигация: для v1 хвост клиппится по границам сегмента строки как binding; полная «wrap-tail хвоста» корректность не требуется — отметить в отчёте, если поведение неидеально. Не блокирует фикс (основной кейс — linear-сборка, не у origin).
- **R2 — reverse-праймер: ориентация оснований хвоста.** Текущий код вписывает в reverse-стрелку top-strand основания (`upper.slice`). Хвост берётся из `hit.tail` (строка 5′→3′). Митигация: Code следует существующей конвенции binding-оснований для reverse; если визуально неоднозначно — §10 Q2.
- **R3 — hit-target расширение ломает клик соседнего праймера.** Перекрытие hit-rect'ов после добавления хвоста. Митигация: hit-target расширяется ровно на `tailW` со стороны 5′; тест §5 на клик.

## §10 Открытые вопросы

1. **Стиль хвоста** — outline / светлая заливка / штриховка. Дефолт: отличный от binding, «свисающий» вид (binding — сплошная заливка, хвост — outline или −40% opacity). Точный стиль — по дизайн-системе, на усмотрение Code; при сомнении — скриншот Игорю.
2. **Вписывать ли основания хвоста** при reverse — если ориентация спорна, для v1 допустимо рисовать сегмент хвоста без вписанных букв (только тело сегмента), буквы — полировкой позже. Code решает по факту.
