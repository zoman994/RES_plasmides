> Аналитическая записка (reference, не спека). Создана 24.05.2026 после изучения
> teemi по запросу Игоря. Источники: репозиторий github.com/hiyama341/teemi,
> статья в PLOS Computational Biology (Petersen, Levassor et al., 2024,

> направление продукта, lab journal, multi-organism, ML-слой.
> Связан с `PRODUCT_BACKLOG_INTEGRATED_WORKBENCH.md` (Q-STRAT), `UX_VISION.md`.

---

## 0. Главное в одной фразе

teemi — это **НЕ редактор плазмид и НЕ конкурент BodgeGene по UI**. Это
Python-библиотека для **всего DBTL-цикла конструирования микробных штаммов**
(Design-Build-Test-Learn), работающая внутри Jupyter-ноутбуков. Конкурирует не с
твоим canvas'ом, а с твоим *направлением* — «интегрированный fungal biotech
workbench». По охвату задач teemi ближе к тому, КУДА ты целишься, чем
OpenCloning. По форме (код в ноутбуках, без GUI) — дальше всего.

---

## 1. Что это и кто за этим стоит

Open-source Python-пакет (MIT, PyPI: `teemi`). Автор — Lucas Levassor + Søren
Petersen, лаборатория Michael Jensen, **DTU Biosustain** (Novo Nordisk Foundation
Center for Biosustainability, Дания) — это сильная синтбио-группа, среди соавторов
Jay Keasling. Опубликовано в PLOS Comp Biol (2024). Не студенческий проект —
институциональный.

Назначение (из описания репозитория): воспроизводимое и FAIR-совместимое
конструирование микробных штаммов — симуляция всего DBTL-цикла, генерация
генетических частей, дизайн библиотек, отслеживание образцов; платформа для
автоматизации задач метаболической инженерии.

Доказательная база: статья — не декларация, а реальный эксперимент. Двумя
DBTL-циклами оптимизировали продукцию стриктозидина (предшественник
алкалоидов) в дрожжах S. cerevisiae — комбинаторная библиотека 1280 вариантов
(8 G8H × 10 CPR × 4 × 4 промотора), 2000+ ML-моделей через AutoML, рост hit-rate
в 5 раз между циклами. То есть teemi прогнали через настоящую задачу
метаболической инженерии и показали результат.

## 2. Парадигма — literate programming, не GUI

Ключевое отличие от всего остального в обзоре. teemi не имеет интерфейса. Рабочий
документ — **Jupyter-ноутбук** (запускается локально или в Google Colab без
установки). Подход «literate programming»: текст протокола на естественном языке
+ исполняемый код вперемешку. Каждый шаг лабораторного протокола привязан к
функции/модулю teemi.

То есть ноутбук teemi одновременно: (а) исполняемая спецификация эксперимента,
(б) электронный лабораторный журнал, (в) FAIR-совместимая запись данных со
ссылками на репозитории.

Это полная противоположность BodgeGene (визуальный canvas) и противоположность
даже OpenCloning (GUI + опциональный скриптинг). teemi — **код-first, целиком**.
Цена: нужны базовые навыки Python. Авторы это смягчают абстракциями и
Colab-ноутбуками, но порог входа всё равно «программистский».

## 3. Пять модулей DBTL — что покрывает

teemi = 4 модуля DBTL + LIMS:

- **DESIGN** — функции для процедур клонирования и генерации комбинаторных
  библиотек. Поиск гомологов через NCBI BLAST по amino-acid identity, выбор
  промоторов по данным экспрессии, дизайн праймеров. Свой алгоритм
  `DesignAssembly` (overhang'и 40 bp по умолчанию, 50/50 на forward/reverse).
- **BUILD** — построение штаммов: симуляция и расчёт PCR, реакции трансформации,
  автогенерация инструкций для лабораторных роботов. Модули `PCR.py`,
  `transformation.py`.
- **TEST** — препроцессинг данных секвенирования, связывание результатов
  секвенирования с генетическими частями через парное выравнивание.
- **LEARN** — ML: готовые функции + графики. В статье — H2O AutoML, 2000+
  моделей (XGBoost, DeepLearning, DRF, GLM, GBM, StackedEnsemble), предсказание
  титров по генотипу, learning curves для stop-go решения «делать ли следующий
  цикл».
- **LIMS** — импорт/экспорт ДНК-последовательностей, отслеживание образцов через
  Benchling API и **локальную CSV-базу** (`csv_database.py`).

BodgeGene сейчас покрывает кусок DESIGN (дизайн сборок, праймеры) и зачаток BUILD
(симуляция операций). TEST и LEARN — у тебя только в backlog (lab journal, gel
OCR/ML). teemi покрывает все четыре + LIMS. По охвату DBTL teemi сильно шире.

## 4. Где пересечение с BodgeGene прямое

1. **Backend-движок — тот же pydna.** teemi построен на pydna (как и
   OpenCloning). Третий независимый сигнал, что pydna — де-факто стандарт
   симуляции операций (рестрикция/лигирование/PCR/Gibson/гомологичная
   рекомбинация) в open-source. Твои самописные модули (mutagenesis, golden-gate,
   restriction-db, tm) делают часть той же работы. Усиливает вопрос из
   `COMPARATIVE_OPENCLONING.md` §7: оценить замену части backend на pydna.
2. **Aspergillus niger в их же данных.** В наборе гомологов CPR статьи фигурирует
   Aspergillus niger (Ani) наряду с растительными видами. То есть грибные
   организмы для них — рабочий материал, не экзотика. Твоя ниша пересекается.
3. **GenBank как формат обмена.** teemi импортирует/экспортирует GenBank-файлы
   (.gb) на каждом шаге — генерирует .gb новых штаммов. Тот же вывод, что по
   OpenCloning: GenBank — лингва-франка, `.bodge` обязан с ним дружить.
4. **Комбинаторные библиотеки как первоклассный объект.** teemi проектирует не
   одну конструкцию, а библиотеку из тысяч вариантов (промотор × ген ×
   организм). У тебя модель — отдельные контейнеры/сборки. Если BodgeGene идёт в
   fungal strain engineering, «библиотека вариантов» — сущность, которой в твоей
   data model пока нет.
5. **CSV-LIMS — дешёвый lab journal.** Их `csv_database.py` — отслеживание
   образцов на простой локальной CSV. Сравни с `CloneCoordinate` (Google Sheets)
   из обзора ландшафта. Оба намекают: твой backlog-пункт «lab journal» не обязан
   начинаться сложно — локальная таблица образцов уже даёт ценность.

## 5. Чего у BodgeGene нет, а у teemi есть — и это направление

- **LEARN-фаза (ML-слой).** teemi замыкает цикл: данные титров/генотипов →
  AutoML → предсказание → рекомендации новых дизайнов на следующий цикл. Это
  отдельная парадигма «инструмент не просто рисует конструкт, а учится на
  результатах и советует». У тебя в `PRODUCT_BACKLOG` это есть как «ML», у них —
  работающий код с доказанным 5× ростом hit-rate.
- **Robot instructions.** BUILD-модуль генерирует инструкции для лабораторных
  роботов (связь с liquid handler'ами). Уровень «in silico → железо».
- **Stop-go аналитика.** Learning curves как количественный критерий «делать ли
  следующий DBTL-цикл». Управленческий слой над экспериментом.
- **Genotype-phenotype data management.** Систематическая привязка генотипа
  (секвенирование) к фенотипу (титры LC-MS) — ядро их TEST/LEARN.

Это всё — «верхние» фазы DBTL. BodgeGene живёт в DESIGN. Вопрос направления: ты
остаёшься мощным DESIGN-инструментом, или BodgeGene тоже тянется к BUILD/TEST/
LEARN. teemi показывает, как выглядит «весь цикл», если туда идти.

## 6. Где BodgeGene объективно сильнее / своя ниша

- **GUI.** teemi требует Python и Jupyter. BodgeGene — визуальный, для биолога
  без кода. Это не отставание от teemi, это разные аудитории. Огромная часть
  биологов код-first инструмент не возьмёт. Твой визуальный путь — реальное
  преимущество для этой аудитории.
- **Интерактивность.** canvas, прямое манипулирование, sequence editor — teemi
  не предлагает ничего подобного, там всё через перезапуск ячеек ноутбука.
- **2024-era UX.** CommandPalette, canvas-skeleton — у teemi UX нет вообще.

То есть teemi и BodgeGene могут НЕ конкурировать напрямую: teemi — для тех, кто
пишет код; BodgeGene — для тех, кто хочет видеть и кликать. Но если оба заявляют
«fungal/microbial strain engineering workbench» — аудитория частично общая, и
надо сознательно понимать, чем ты для неё лучше (ответ: визуальностью и порогом
входа), а чем пока нет (ответ: охватом DBTL и ML).

## 7. Конкретные выводы для BodgeGene

НЕ задачи. Вход для решения Игоря. Приоритезированы.

1. **Развилка направления — главное.** teemi даёт ясную картину «весь DBTL».
   Решить сознательно: BodgeGene = сильный DESIGN-инструмент с отличным UX, или
   BodgeGene тянется к BUILD/TEST/LEARN. Это стратегический вопрос (Q-STRAT),
   не фича. От ответа зависит data model (нужна ли «библиотека вариантов»,
   «штамм», «титр»).
2. **pydna — оценить серьёзно.** Третий инструмент подряд (OpenCloning, teemi +
   сам pydna) на нём. Твоё «backend работает кривовато» может частью лечиться
   заменой самописных модулей на pydna. Не Звено, не сейчас — Q-STRAT.
3. **«Библиотека вариантов» как сущность.** Если идём в strain engineering —
   комбинаторная библиотека (промотор × ген × организм) не моделируется твоими
   контейнерами. Это пробел data model. Связать с `LIBRARY_MODEL_DRAFT.md`.
4. **Lab journal можно начать дёшево.** CSV-LIMS teemi + Google-Sheets-подход
   CloneCoordinate: твой backlog-пункт «lab journal» не требует сложного старта.
   Локальная таблица образцов (контейнер → где лежит → статус) уже полезна.
5. **ML-слой — далёкий ориентир, не игнорировать.** LEARN-фаза teemi с доказанным
   результатом показывает, что «инструмент учится на результатах» — не фантазия.
   Держать как долгосрочное направление `PRODUCT_BACKLOG`, не как близкую задачу.

## 8. Чего НЕ копировать

- **Code-first парадигму.** Literate programming — сила teemi и одновременно их
  ограничение по аудитории. Твой визуальный путь сознателен. Не поддаваться
  ощущению «у них серьёзнее, потому что код» — это просто другая аудитория.
- **Объём DBTL сразу.** teemi — институциональный проект целой лаборатории.
  Пытаться закрыть весь DBTL силами личного инструмента — расфокус. Если идти в
  BUILD/TEST — то по одной фазе, не разом.

## 9. teemi vs OpenCloning vs BodgeGene — одной таблицей

| | BodgeGene | OpenCloning | teemi |
|---|---|---|---|
| Форма | веб-GUI, canvas | веб-GUI, «family tree» | Python-пакет в Jupyter |
| Аудитория | биолог без кода | биолог без кода | биолог с Python |
| Охват DBTL | DESIGN (+зачаток BUILD) | DESIGN | весь DBTL + LIMS |
| Backend-движок | свой (+BioPython) | pydna | pydna |
| Формат | `.bodge` | `.json` (LinkML) | Jupyter + GenBank + CSV |
| ML / LEARN | backlog | нет | есть (AutoML) |
| Robot integration | нет | частично (через j5/Opentrons экосистему) | есть |
| Фокус организма | грибы (цель) | generic | микробы/дрожжи (+грибы в данных) |
| Зрелость | alpha, личный | v1.3, институционально | опубликован, институционально |
