# BodgeGene — Система документации

**Цель:** Нулевая потеря контекста между сессиями Claude Chat и между `/clear` в Claude Code.

---

## Иерархия файлов

```
RESplasmide/
│
├── CLAUDE.md              ← 🔵 СТАТИЧНЫЙ. Архитектура, правила, структура.
│                             Меняется РЕДКО (при добавлении новых компонентов).
│                             Claude Code читает ПЕРВЫМ.
│
├── PROJECT_STATE.md       ← 🟡 ЖИВОЙ. Текущий статус проекта.
│                             ЧТО сделано, ЧТО не работает, ЧТО дальше.
│                             Обновляется Claude Chat В КОНЦЕ каждой сессии.
│                             Claude Chat читает ПЕРВЫМ при старте.
│
├── CURRENT_TASK.md        ← 🔴 ОДНОРАЗОВЫЙ. Конкретная задача для Claude Code.
│                             Перезаписывается перед каждой задачей.
│                             Claude Code читает, выполняет, отчитывается.
│                             После выполнения → Игорь подтверждает → очищается.
│
├── DECISIONS.md           ← 🔵 APPEND-ONLY. Архитектурные решения.
│                             Никогда не удаляются, только добавляются.
│                             Формат: [ДАТА] Решение. Причина.
│
├── PALETTE_SPEC.md        ← 🔵 СПЕКА. Дизайн палитки и режимов UI.
│                             Меняется только при пересмотре дизайна.
│
├── TEST_RESULTS.md        ← 🟡 ЖИВОЙ. Результаты тестирования.
│                             Обновляется после каждого прогона тестов.
│
├── CHANGELOG.md           ← 🟡 APPEND-ONLY. Лог изменений.
│                             Дописывается после каждой сессии.
│
└── docs/
    └── PLASMID_OPERATIONS.md  ← 🔵 СПЕКА. Модуль работы с плазмидами.
```

## Протокол обновления

### 1. Начало сессии Claude Chat

```
Claude Chat читает:
  1. PROJECT_STATE.md → где мы, что сделано, что сломано
  2. DECISIONS.md     → какие решения приняты (не пересматривать)
  3. Memory           → высокоуровневый контекст

Claude Chat НЕ читает (пока не нужно):
  - CLAUDE.md        → для Claude Code
  - CURRENT_TASK.md  → для Claude Code
  - весь исходный код → только по запросу
```

### 2. Проектирование (Claude Chat + Игорь)

```
Обсуждаем → принимаем решение → Claude Chat записывает:
  - DECISIONS.md += [ДАТА] новое решение
  - Если нужна спека → создаём/обновляем *_SPEC.md
  - Если задача для кода → записываем CURRENT_TASK.md
```

### 3. Передача задачи Claude Code

```
Игорь говорит Claude Code:
  "Прочитай CLAUDE.md, затем CURRENT_TASK.md, выполни."

Claude Code:
  1. Читает CLAUDE.md → понимает архитектуру
  2. Читает CURRENT_TASK.md → понимает задачу
  3. Выполняет
  4. Запускает npx vite build && npx vitest run
  5. Отчитывается Игорю
  6. /clear
```

### 4. Тестирование (Игорь + Claude Chat)

```
Игорь:
  - Тестирует в браузере
  - Скриншоты → Claude Chat
  
Claude Chat:
  - Диагностирует баги
  - Обновляет TEST_RESULTS.md
  - Пишет новый CURRENT_TASK.md если нужны фиксы
```

### 5. Конец сессии Claude Chat

```
ОБЯЗАТЕЛЬНО перед закрытием чата:
  1. Обновить PROJECT_STATE.md:
     - Что сделали в этой сессии
     - Какие баги найдены/исправлены
     - Что дальше
  2. Обновить CHANGELOG.md:
     - Дата + краткий список изменений
  3. Обновить DECISIONS.md (если были новые решения)
  4. Обновить Memory (если нужно)
```

## Формат каждого файла

### PROJECT_STATE.md — главный "мозг"

```markdown
# Состояние проекта
**Последнее обновление:** [дата, время]

## Статус модулей
Таблица: модуль | статус | готовность%

## Что сделано в последней сессии
Краткий список

## Активные баги
Таблица: # | приоритет | описание | файл

## Следующие шаги
Нумерованный список: что делать дальше

## Ключевые файлы для контекста
Список файлов с кратким описанием что в каждом
```

### CURRENT_TASK.md — задача для кода

```markdown
# Текущая задача
**Статус:** Ready / In Progress / Done
**Приоритет:** HIGH / MEDIUM / LOW

## Контекст
Зачем это нужно (1-2 предложения)

## Задачи
1. Файл: ... Что сделать: ...
2. Файл: ... Что сделать: ...

## Верификация
Команды для проверки + ручные тесты

## После выполнения
Сообщить Игорю результат
```

### DECISIONS.md — решения

```markdown
# Архитектурные решения

[2026-03-29] Два типа объектов в палитке: Плазмиды и Запчасти.
Причина: плазмида = кольцевая + ≥2 региона, нужен другой workflow (wizard).

[2026-03-29] CDS валидация organism-aware.
Причина: у прокариот нет интронов, кнопка "Разметить интроны" вводит в заблуждение.

[2026-03-XX] ...следующее решение...
```

## Правила для Claude Chat (я)

1. **Начало сессии:** ВСЕГДА читай PROJECT_STATE.md первым
2. **При проектировании:** записывай решения в DECISIONS.md немедленно
3. **При передаче задачи:** пиши CURRENT_TASK.md с полной спекой
4. **При тестировании:** обновляй TEST_RESULTS.md с результатами
5. **Конец сессии:** ОБЯЗАТЕЛЬНО обновить PROJECT_STATE.md + CHANGELOG.md
6. **НЕ полагайся на memory** для деталей — memory для высокоуровневого контекста

## Правила для Claude Code

1. **Начало задачи:** читай CLAUDE.md → CURRENT_TASK.md
2. **Не читай другие MD файлы** если не указано в задаче
3. **После выполнения:** `npx vite build && npx vitest run`
4. **`/clear` после каждой задачи** — не копи контекст

## Правила для Игоря

1. **Передача задачи коду:** "Прочитай CLAUDE.md и CURRENT_TASK.md, выполни"
2. **Тестирование:** скриншоты → Claude Chat
3. **Проблемы:** опиши словами + скриншот, Claude Chat диагностирует
4. **НЕ правь MD файлы вручную** — пусть Claude Chat поддерживает актуальность
