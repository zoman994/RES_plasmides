## Левый sidebar (StartScreen.Sidebar — единый shell)

### Кнопка «+ Создать проект» (^N)

**Сейчас:** создаёт пустой `.bodge`-проект. Активирует его.
**Оставляем как есть.** Это одна из двух точек входа создания контейнера-проекта (вторая — импорт `.bodge`). Хоткей `^N` — норма.

### Кнопка «↑ Открыть .bodge...» (^O) и «↓ Импорт .gb / .dna...»

**Сейчас:** две разные кнопки. «Открыть .bodge» — загружает проект, делает активным. «Импорт .gb/.dna» — импортирует одну плазмиду в библиотеку.

**Проблема в свете DEC-PROJECT-OPEN-MERGE-01:** «Открыть» как операция должно слиться с импортом. Импорт `.bodge` = активация.

**Что меняем:**
- Переименовать **«↑ Открыть .bodge...»** → **«↑ Загрузить .bodge...»** (или **«Импортировать .bodge»**). Семантика та же — но название перестаёт намекать на «отдельную операцию открытия». Импорт всегда открывает.
- **«↓ Импорт .gb / .dna...»** оставить как есть — это импорт одной плазмиды, не проекта. Концептуально другое (один контейнер vs целая коробочка).

**Альтернатива (более радикальная):** объединить обе кнопки в одну **«↑ Загрузить файл...»** с auto-detection по расширению. `.bodge` → новый проект + активация. `.gb/.dna/.fasta` → запись в текущую активную зону (проект или БЕЗ ПРОЕКТА). Минус — теряется visibility «у меня два разных типа загрузки». Решать биологу.

### РАБОЧЕЕ МЕСТО — пункты меню

**Сейчас:**
- Главная
- Библиотека 142 (активна)
- Конструкции (soon)
- Реакции (soon)
- Праймеры (soon)

**Проблема:** «Конструкции» и «Реакции» — это **режимы отображения активного проекта**, не отдельные top-level workspace'ы. По архитектуре 09.05.2026:
- DAG проекта = «Конструкции».
- Рёбра в DAG = «Реакции».
- DAG живёт в правой панели Library, не в отдельном экране.

То есть кликая на проект в Tree биолог уже видит DAG справа. Дублировать «Конструкции» как пункт меню — лишнее.

**Что меняем:**

Вариант А — минимальный (рекомендую):
- **Главная** — оставить (StartScreen главная).
- **Библиотека** — оставить, она и есть всё (Tree + Inspector / DAG в правой панели в зависимости от того, что выбрано).
- **Конструкции (soon), Реакции (soon)** — **убрать**. Они не понадобятся.
- **Праймеры (soon)** — оставить **только** если планируется отдельный экран (а не вкладка внутри Library Inspector). Скорее это Tab внутри Library, а не пункт меню. Тогда тоже убрать.

Вариант Б — расширенный:
- Оставить «Праймеры» как отдельный экран = глобальный View поверх всех primer entries проекта (с фильтрами по статусу заказа, Tm, использованию). Это согласуется с DEC-NAV-3LEVEL-01 «Library tab Праймеры».

Я бы выбрал Б на полу-перспективу, А на сейчас.

### Структура зон

**Сейчас:**
- 🚩 К. личная подборка плазмид 190 (= БЕЗ ПРОЕКТА)
- 📦 32132131.BODGE [active]
- 📦 НОВЫЙ ПРОЕКТ.BODGE [active] (выделен)

**Проблема:**
1. **Имя зоны «К. личная подборка плазмид»** — длинное, с непонятным «К.». По архитектуре эта зона должна называться `⎀ БЕЗ ПРОЕКТА` (свободный стол биолога). Переименовать.
2. **Тег `[active]` на двух проектах одновременно** — это ошибка модели или разрешено по дизайну? По архитектуре активный — **один**. Если оба `[active]` — что-то не сходится. Возможно, тег значит «открыт хоть раз» / «импортирован», а активный по факту — выделенный фоном (НОВЫЙ ПРОЕКТ.BODGE сейчас визуально активен через жёлтый highlight на kanMX). Нужно прояснить семантику тега.

**Что меняем:**
- **Переименовать «К. личная подборка плазмид» → «⎀ БЕЗ ПРОЕКТА»** или просто **«Свободный стол»**. Без «К.», без длинного описания.
- **Тег `[active]`** — оставить **только на одном** проекте — на текущем активном. Остальные .bodge без тега. По клику на заголовок другого проекта — тег `[active]` переезжает.

### Внутри проекта — Контейнеры / DAG / Праймеры

**Сейчас:** три папки внутри каждого проекта. «DAG» как папка с числом записей.

**Проблема:** «DAG» — это **режим отображения** проекта, не контейнер записей. Класть его в Tree как папку — путает. Граф появляется в правой панели когда биолог кликает по заголовку проекта или по «Контейнеры».

**Что меняем:**
- **«Контейнеры»** — оставить, это нормальный список плазмид/фрагментов проекта.
- **«DAG»** как узел в Tree — **убрать**. DAG показывается в правой панели автоматически когда выбран проект (или его узел «Контейнеры» / «Праймеры»).
  - Альтернатива: оставить «DAG» как переключатель режима правой панели (Inspector vs DAG), но тогда это не папка с числом — это **toggle**. Жанрово неправильно для tree-view.
- **«Праймеры»** — оставить, это нормальный list view для primer entries проекта.

## Bottom-bar Inspector (главные действия)

### «🔵 Использовать в активном»

**Сейчас:** добавить эту плазмиду в активный проект как новый контейнер.

**Проблема:** что значит «использовать»? Биолог может подумать «начать использовать в опытах» (физически), а это значит «скопировать в активный проект как новый узел DAG». Семантика расплывчатая.

**Что меняем:**
- Переименовать в **«Добавить в активный проект»** или **«Скопировать в активный»**. Прямее.
- **Disabled** когда активный проект пуст (`БЕЗ ПРОЕКТА` зона) с tooltip «Нет активного проекта — выбери в Tree или создай новый».
- Если плазмида уже в активном проекте — кнопка показывает **«Открыть в DAG»** или прячется (мы уже в этом проекте, действие бессмысленно).

### «↗ Открыть»

**Сейчас:** открыть Container Window (или fullscreen Inspector?).

**Проблема:** двойной клик по записи в Tree уже открывает Container Window (по DEC-NAV-3LEVEL-01 точка входа). Кнопка дублирует жест. Биолог видит две одинаковые точки входа — лишний шум.

**Что меняем:**
- **Убрать кнопку «Открыть»**. Двойной клик по плазмиде в Tree остаётся единственной точкой входа в Container Window.
- Альтернатива (если кнопка нужна для discoverability) — переименовать в **«Открыть в Container Window»** или **«Полный редактор»** (после M-C.2 это будет точное название). Сделать иконкой ⤢ (fullscreen) рядом с именем плазмиды, не как отдельную кнопку в bottom-bar.

### «✏️ Manual-edit ветка»

**Сейчас:** создать новую версию плазмиды через manual edit (DEC-LIB-K10-MANUAL-BRANCH-01).

**Проблема:** «ветка» — программистский жаргон. Биолог не «ветвит репозиторий», он **«делает копию для ручной правки»**.

**Что меняем:**
- Переименовать в **«✏️ Создать копию для правки»** или **«Новая версия для ручной правки»** или просто **«✏️ Редактировать»** (если флоу такой: клик → копия + переход в редактор).
- В свете DEC-CONTAINER-DIFF-STORAGE-01 эта операция автоматически использует diff-режим. Биологу неважно как хранится — название должно отражать **намерение** («хочу поправить, не теряя оригинал»).

### «📁 Переместить»

**Сейчас:** перемещение записи между зонами/папками.

**Оставляем.** Полезно. Может быть переименовать в **«Переместить в папку...»** для прозрачности (открывает picker папки).

### «↓ Экспорт»

## Что делать с этим ревью

Это **не реализация**, это план переименований и реорганизации. Часть правок дешёвые (переименования строк через `lib/strings.js`), часть требуют рефакторинга (убрать «Конструкции/Реакции» из меню, убрать «DAG» из Tree).

**Группировка по стоимости:**

### Дёшево — переименования (можно одной сессией Code, тип C)
- «↑ Открыть .bodge...» → «↑ Загрузить .bodge...»
- «К. личная подборка плазмид» → «⎀ БЕЗ ПРОЕКТА» / «Свободный стол»
- «🔵 Использовать в активном» → «🔵 Добавить в активный проект»
- «✏️ Manual-edit ветка» → «✏️ Создать копию для правки»
- «📁 Переместить» → «📁 Переместить в папку...»

### Средне — реорганизация Tree и меню (тип B)
- Убрать «Конструкции», «Реакции» из РАБОЧЕЕ МЕСТО (опционально «Праймеры»).
- Убрать «DAG» как узел внутри проекта в Tree.
- Тег `[active]` только на одном проекте.

### Большое — функциональные правки
- Дропдаун последних проектов в топ-баре по клику на «Без активного проекта».
- Disable / context-aware «Добавить в активный проект».
- Убрать кнопку «Открыть» в bottom-bar (двойной клик единственная точка входа).
- Hover-revealed quick-add icon вместо стрелки ↑ на записях Tree.
- Вкладка «История» в Inspector после реализации DEC-CONTAINER-DIFF-STORAGE-01.

### Когда делать

- **Дёшево** — можно сразу, в любом порядке (даже параллельно с Стадиями 1-2 из roadmap'а). Тип C, мини-спека.
- **Средне** — в рамках **Стадии 2 (Project Activation merge)**. Логично — там же реализуем DEC-PROJECT-OPEN-MERGE-01, заодно чистим UX.
- **Большое** — частично в Стадии 2 (дропдаун проектов, disable add-to-active), частично в Стадии 3 (вкладка История + контекст-зависимое поведение Inspector в свете Container Window).
