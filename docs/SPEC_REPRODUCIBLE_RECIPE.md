# SPEC — Reproducible Recipe · «Воспроизводимый рецепт сборки»

**Тип:** feature (design-спека, vision-уровень) · разбивка на K-задачи — на хэндофе Code.
**Дата:** 2026-06-17 · **Автор:** Игорь ↔ Claude
**Расширяет:** `BODGE_V2_PROVENANCE_SCHEMA_PLAN.md` (граф провенанса = субстрат рецепта), `PLASMID_GIT_REVIVE_DESIGN.md` (replay оси B), `CANVAS_DESIGN_PROPOSAL.md` (bipartite Material/Reaction), `SPEC_BODGE_FORMAT_V2_CORE.md` (ZIP-формат, containers/*.gb, assemblies/*.json).
**Связано:** [[reproducible-recipe]], [[plasmid-git]], будущая [[autolab]] (fork-a-recipe → batch).

> **Суть в одном предложении:** конструкт экспортируется не картинкой и не прозой, а **самодостаточным пере-исполняемым рецептом** — упорядоченным графом операций со вшитыми последовательностями всех частей, который любой может *прочитать как чистый Methods*, *пере-прогнать* и *сверить хэш продукта*. «Dockerfile + lockfile для плазмиды».

---

## 0. TL;DR

Сегодня, чтобы воспроизвести чужой конструкт из статьи, нужно распутать абзац прозы («вырезали → обработали нуклеазой → взяли кастомный вектор pNET, описанный в [12]…») и догнать ДНК по ссылкам на другие работы. **Рецепт это убивает:** в supplement кладётся один файл, в котором (а) **все части вшиты** (никаких «см. другую работу»), (б) операции записаны как **исполняемый граф**, (в) есть **авто-Methods** и схема сборки для чтения, и (г) пере-прогон **проверяемо** даёт тот же продукт (sha256-совпадение → бейдж «✓ воспроизводимо»).

Главное: это **не новая система**, а **экспорт/replay/render-вид** провенанс-графа, который формат `.bodge v2` **уже кодирует** (`operations[]` = ось A, edit-`commits[]` = ось B). Мы добавляем три слоя поверх готового субстрата.

## 1. Проблема

**Игорь (verbatim, мотивация):**
> «часто ты видишь в статьях - мы собирали так то так то, с кучай нагромождений в виде вырезали, обработали нуклеазой потом взяли веткор рНЕТ он касомный описанный в другой работе, и пока докопаешься до конструкта охуеешь. А тут просто в саплаймент кинул сборку и норм»

Боль в трёх измерениях:
1. **Непрозрачность.** Construction закопан в Methods-прозу, неоднозначен, легко упустить шаг/параметр.
2. **Не самодостаточно.** «Вектор кастомный, описан в [ref]» → квест по ссылкам, часто тупиковый (ДНК нет нигде).
3. **Не воспроизводимо.** Нельзя *запустить* описание и проверить, что получится именно заявленный конструкт.

Кризис воспроизводимости в молекулярной биологии — системный; «construction record» почти никогда не бывает машинно-проверяемым.

---

## 2. Видение

Рецепт = **сериализованный граф провенанса конструкта** с тремя «лицами»:

| Лицо | Что это | Для кого |
|---|---|---|
| **Машинное** (lockfile) | упорядоченные шаги с *закреплёнными* входами (ДНК/sha256, ферменты, праймеры, параметры) | инструмент / робот / pydna-подобный replay |
| **Самодостаточный bundle** | `.bodge` ZIP, где **вшиты** все материалы (containers/*.gb) + пул праймеров | supplement статьи, передача коллеге |
| **Человеческое** (авто-Methods + схема) | чистый текст методов + диаграмма сборки, сгенерированные из графа | читатель / reviewer / сам автор |

И **верификация**: продукт = чистая функция (входы + операции) → пере-прогон → sha256-сверка → **«✓ воспроизводимо»**.

---

## 3. Ключевой инсайт — формат уже хранит граф

Из `BODGE_V2_PROVENANCE_SCHEMA_PLAN` (§1): `.bodge v2` **уже** bipartite-граф «материалы ↔ реакции»:

- **Ось A (что собирали)** = `assemblies/<zoneId>.json → operations[]`: `{id, kind, inputs, inputPieces, outputs, params, junctionRefs, materializedClones[], executedAt}`. **Это и есть шаги рецепта.**
- **Ось B (правки последовательности)** = `containers/<id>.gb` COMMENT `commits[]` (plasmid-git форма, **replay-able**).
- **Материалы** = `pieces[]` + `containers/<id>.gb` (валидный GenBank, самодостаточная ДНК).
- **Праймеры** = пул `primers.json` (Δ3), реакции ссылаются `primerPairId`.
- `materializedClones[]` — лабораторный исход на ребре (Sanger verified/failed + notebook).
- `schema_version` (semver) + миграции `bodge-migrations/` — версионирование без wipe.

**Вывод:** рецепт = `.bodge`-bundle + `recipe.json` (упорядоченный вид графа + product-hash) + авто-render. Мы **переиспользуем** субстрат, а не строим параллельный.

---

## 4. Модель и глоссарий

- **Recipe** — самодостаточный bundle: `recipe.json` (манифест шагов + продукт-хэш + метаданные) + `containers/*.gb` (вшитые материалы) + `primers.json` + сгенерированный `METHODS.md` + `diagram.svg`.
- **Step** — один шаг рецепта = одна операция оси A (`pcr/restriction/gibson/golden_gate/ligation/kld/gateway`) **или** агрегированная правка оси B.
- **Material** — узел: исходный контейнер или промежуточный продукт (piece), с ДНК (GenBank) + sha256.
- **Edit-commit** — атомарная правка последовательности (ось B), replay-able.
- **Product hash** — sha256 финального продукта (через `resource-hash`); якорь воспроизводимости.
- **Reproducible badge** — статус: пере-прогон шагов даёт продукт с тем же sha256.

## 5. Спецификация формата

### 5.1 `recipe.json` (манифест-lockfile)

```jsonc
{
  "recipeVersion": "1.0",
  "tool": { "name": "BodgeGene", "version": "0.8.7-alpha", "enzymeDb": "re-db@v1" },
  "product": {
    "name": "pXYZ", "length": 3412, "topology": "circular",
    "sha256": "sha256-9f1a…", "container": "containers/cXYZ.gb"
  },
  "materials": [
    { "id": "c_puc19",  "name": "pUC19",        "container": "containers/c_puc19.gb",  "sha256": "sha256-aa…", "role": "backbone" },
    { "id": "c_tmpl",   "name": "gDNA template","container": "containers/c_tmpl.gb",   "sha256": "sha256-bb…", "role": "template" }
  ],
  "primers": [
    { "id": "p1", "name": "P1_fwd", "direction": "fwd", "tail": "GCTAGC", "binding": "ATGGTG…", "tm": 60.2 },
    { "id": "p2", "name": "P2_rev", "direction": "rev", "tail": "GGATCC", "binding": "TTACTT…", "tm": 59.8 }
  ],
  "steps": [
    { "n": 1, "op": "pcr",
      "inputs": ["c_tmpl"], "params": { "primerPair": ["p1","p2"], "range": { "start": 100, "end": 700 } },
      "output": "m_insert", "outputSha256": "sha256-cc…" },
    { "n": 2, "op": "restriction",
      "inputs": ["c_puc19"], "params": { "enzymes": ["EcoRI","BamHI"], "buffer": "CutSmart" },
      "output": "m_backbone", "outputSha256": "sha256-dd…" },
    { "n": 3, "op": "gibson",
      "inputs": ["m_backbone","m_insert"], "params": { "overlapLen": 25, "circular": true },
      "output": "cXYZ", "outputSha256": "sha256-9f1a…" }    // == product.sha256
  ],
  "axisB": [   // правки последовательности (если были), replay-able
    { "container": "cXYZ", "commits": [
      { "id":"e1", "type":"substitution", "parentPos":412, "payload":{"newBase":"A"}, "label":"G412A" } ] }
  ],
  "verification": { "reproducible": true, "verifiedAt": "2026-06-17T…", "engineVersion": "0.8.7-alpha" }
}
```

**Маппинг на формат:** `steps[]` ← `operations[]` (ось A, типизированные `params` по Δ1); `materials[]`/`output` ← `pieces[]`+`containers/*.gb`; `primers[]` ← пул (Δ3); `axisB[]` ← COMMENT-commits (Δ2). Дискриминатор шага = `op`, `params` — типизированный вариант (как Δ1).

### 5.2 Self-contained bundle (recipe-export-профиль `.bodge`)

Рецепт — это `.bodge` ZIP с recipe-профилем в manifest:
```
recipe-pXYZ.bodge (ZIP)
├── manifest.json         // profile: "recipe", schema_version, product ref
├── recipe.json           // §5.1
├── containers/*.gb       // ВШИТЫ все материалы (вектор pNET — тоже внутри!)
├── primers.json          // пул
├── METHODS.md            // авто-сгенерированный (§5.3)
└── diagram.svg           // схема сборки (§5.4)
```
**Принцип самодостаточности:** ни один материал не описан ссылкой — ДНК всех частей физически в bundle (это весь смысл «не смотри другую работу»). Открывается в BodgeGene и (через GenBank) в SnapGene/любом редакторе.

### 5.3 Авто-Methods — правила рендеринга (граф → проза)

Каждый `op` → шаблон-предложение (i18n; ниже RU):

| op | Шаблон |
|---|---|
| `pcr` | «{output} ({len} bp) наработан ПЦР с матрицы *{template}* праймерами {fwd}/{rev} (Tm {tm}°C).» |
| `restriction` | «*{input}* расщеплён {enzymes} ({buffer}) → {output} ({len} bp, {ends}-концы).» |
| `gibson` | «{inputs} собраны методом Gibson (перекрытие {overlap} bp){, кольцевой} → **{output}** ({len} bp).» |
| `golden_gate` | «{inputs} собраны Golden Gate ({enzyme}; fusion-сайты {sites}) → **{output}**.» |
| `ligation` | «{inputs} лигированы ({ends}) → **{output}**.» |
| `kld` | «Сайт-направленный мутагенез (KLD) на *{input}*, праймеры {fwd}/{rev} → {output}.» |
| ось B | «*{container}*: внесена правка **{label}** ({from}→{to}) в позиции {pos}.» |

Рендер = топологический проход графа (от исходных материалов к продукту), нумерация шагов, сборка абзаца + список материалов/праймеров в конце. Финал: «**Итог:** {product} ({len} bp, {topology}). Хэш: {sha256[:12]}.»

### 5.4 Build-диаграмма

Bipartite-схема: материалы — прямоугольники, реакции — ромбы/узлы, рёбра `вход → op → выход`. Визуально как уже сделанный `VersionTimeline`, но граф construction-DAG (а не родословная версий). SVG, кликабельные узлы (→ открыть материал/шаг).

## 6. Три лица — детально

### 6.1 Construction record (человеческое) — **доступно сейчас**
Авто-Methods (§5.3) + диаграмма (§5.4) из имеющегося лога операций/версий. Экспорт `METHODS.md` (+ встроенная SVG → PDF). In-app панель «Construction record» на контейнере-продукте. **Не требует replay** — строится из того, что уже записано. Это первый и самый дешёвый слой, и он один уже убивает прозу.

### 6.2 Self-contained bundle — **поверх готового `.bodge`-экспорта**
Recipe-профиль (§5.2): собрать ZIP, вшить ДНК всех материалов, сгенерировать `recipe.json`+`METHODS.md`+`diagram.svg`. Опирается на `bodge-export-profiles.js`.

### 6.3 Replay + верификация — **«воспроизводимо ✓»**
«Запустить рецепт» → движок переигрывает `steps[]` (ось A через `realiseAssembly`) + `axisB[]` (plasmid-git replay) → пересчитывает `outputSha256` каждого шага → сверяет с записанными → продукт-хэш сверяется с `product.sha256`. Все совпали → **«✓ воспроизводимо»**; расхождение → показать первый разошедшийся шаг (где сломалось). Зависит от зрелости replay (см. §13 риски).

### 6.4 Fork-a-recipe — **мост в автолабу**
Пометить вход шага как **переменный** (например, промотор-материал) → подменить → пере-прогон → вариант-продукт. Один переменный вход = шаблон; множество = комбинаторная матрица → **batch/автолаба** (отдельная нить [[autolab]]).

## 7. Контракт детерминизма (ядро «воспроизводимости»)

Продукт обязан быть **чистой функцией** (материалы + шаги + параметры). Чтобы хэш совпадал у любого:
- **Вшить всё, что влияет на продукт:** ДНК материалов, последовательности/tail/binding праймеров, ферменты+версия БД, параметры (overlap, range, enzymes, fusion sites).
- **Исключить из хэшируемой нагрузки** недетерминированное/косметическое: `executedAt`, автор, имена, порядок ключей (канонизировать JSON), локаль. Хэшируем только семантику продукта (через `resource-hash`: sequence+topology+ends).
- **Пиннинг версий:** `tool.version` + `enzymeDb` в `recipe.json`; при replay другой версией движка, давшей другой результат — честный warning «движок изменился, результат может отличаться», не молчаливый зелёный.
- **Движки уже чистые** (primer/restriction/gibson — pure-функции), что делает контракт достижимым.

## 8. Сквозной пример (сердце спеки — читаемость)

**Задача:** вставить ПЦР-фрагмент гена X в pUC19 по EcoRI/BamHI через Gibson → pXYZ.

**Что видит человек (авто-Methods, рендер из графа):**
> **Конструкт pXYZ (3 412 bp, кольцевой).**
> 1. Фрагмент *insert* (601 bp) наработан ПЦР с матрицы *gDNA template* праймерами P1_fwd/P2_rev (Tm 60 °C).
> 2. *pUC19* расщеплён EcoRI + BamHI (CutSmart) → *backbone* (2 811 bp, липкие концы).
> 3. *backbone* + *insert* собраны методом Gibson (перекрытие 25 bp, кольцевой) → **pXYZ** (3 412 bp).
> *Итог:* pXYZ · хэш `9f1a4c2e…`. Материалы и праймеры — в bundle.

**Схема (build-диаграмма, §5.4):**
```
[gDNA template] ──PCR(P1/P2)──▶ (insert 601)
                                      │
[pUC19] ──Cut(EcoRI+BamHI)──▶ (backbone 2811) ──┐
                                      └──────────┴──Gibson(25bp,⟳)──▶ ❰pXYZ 3412❱ ✓воспроизводимо
```

**Что лежит в файле:** `recipe.json` (§5.1) + `containers/{c_puc19,c_tmpl,cXYZ}.gb` (вшиты) + `primers.json` + `METHODS.md` + `diagram.svg`. Reviewer открыл `recipe-pXYZ.bodge` → прочитал Methods, увидел схему, нажал «Запустить» → пере-собралось в идентичный pXYZ → **✓**.

## 9. UX

- **Вход:** на контейнере-продукте — кнопка/пункт **«Рецепт сборки»** (рядом с экспортом) → вкладки *Methods · Схема · Файл*. Принцип двух кликов: продукт → «Рецепт» → «Экспорт в supplement».
- **Экспорт:** `recipe-<name>.bodge` (self-contained) + опц. `METHODS.md`/PDF отдельно.
- **Верификация:** кнопка **«Запустить рецепт»** → прогресс по шагам → бейдж «✓ воспроизводимо» / «✗ расхождение на шаге N».
- **Импорт чужого рецепта:** drop `.bodge` recipe → открывается как construction record + кнопка «Запустить»/«Форкнуть».
- **Пустое состояние:** если у контейнера нет графа операций (импортирован как готовая плазмида) — честно: «Нет записанной сборки; рецепт доступен для конструктов, собранных в BodgeGene» (+ предложить ось B, если были правки).

## 10. Prior art и дифференциация

- **OpenCloning / pydna** — уже есть «re-executable cloning strategy» (JSON + pydna replay). **Дифференциация BodgeGene:** (1) самодостаточный bundle (ДНК вшита, ноль внешних ссылок), (2) авто-Methods + диаграмма для supplement из того же графа, (3) верификация хэшем как first-class бейдж, (4) local-first в полированном редакторе, (5) единый граф охватывает И сборку (ось A), И правки последовательности (ось B). OpenCloning — формат+скрипты; здесь — среда.
- **SnapGene** — embedded History внутри `.dna`, но не портативный пере-исполняемый рецепт и не авто-Methods; file-bloat.
- **Benchling** — workflows/audit, но cloud-locked и без самодостаточного оффлайн-артефакта.

## 11. Архитектурные решения

1. **Рецепт = вид провенанс-графа, не новая модель.** Источник истины — `operations[]` (ось A) + COMMENT-commits (ось B). Рецепт их сериализует/рендерит/реплеит. (Иначе — два расходящихся представления сборки.)
2. **⚓ Самодостаточность обязательна.** Материалы вшиваются (ДНК внутри bundle), не ссылаются. Это определяющее свойство против «см. другую работу».
3. **Хэш только семантики продукта.** `resource-hash` (sequence+topology+ends); метаданные/время — вне хэша. Гарантирует совпадение у разных людей/времён.
4. **Человеческое лицо — first-class, и идёт первым.** Авто-Methods+диаграмма доступны без replay и поставляются Фазой 1.
5. **Версии движка пиннятся; расхождение — громкий warning**, не молчаливый зелёный (принцип §9 VISION «громко о молчаливых сбоях»).
6. **Fork — тот же replay с подменой входа** → переиспользуется в автолабе (не отдельный механизм).

## 12. Scope

### IN
- Новый `recipe.json` shape + сериализатор из `operations[]`/`pieces`/`primers`/axisB.
- Recipe-export-профиль в `bodge-export-profiles.js` (self-contained ZIP).
- Авто-Methods рендерер (граф → markdown) + build-диаграмма (SVG).
- Replay-верификатор (ось A через `realiseAssembly`, ось B через plasmid-git) + хэш-сверка + бейдж.
- UX: панель «Рецепт сборки» на контейнере-продукте + импорт/запуск.

### OUT (отложено)
- **Fork/batch/автолаба** — отдельная нить [[autolab]] (рецепт лишь готовит почву п.6).
- **SBOL3-export** — Δ5b формата, отдельно.
- **Robot-export** (Opentrons/Echo) — в автолабе.
- **Полный round-trip оси B** — зависит от `PLASMID_GIT_REVIVE` (Фаза 3, не Фаза 1).

## 13. Предположения и риски

**Предположения:**
- `operations[]` несут достаточно для replay (inputs/params/outputs). Источник: `BODGE_V2_PROVENANCE_SCHEMA_PLAN §1`. Проверено: частично — Δ1 (типизация params) может потребоваться до надёжного replay.
- Движки сборки детерминированы (pure). Источник: QA fix-pack (pure-функции). Проверено: да.
- `resource-hash` стабилен для (sequence, topology, ends). Источник: `librarySlice`/`computeResourceHash`. Проверено: да (используется в версиях).

**Риски:**
1. **Replay-зрелость (ось A+B).** Граф операций/edit-replay частью на roadmap (`PLASMID_GIT_REVIVE`). *Митигация:* Фаза 1 (человеческое лицо) не зависит от replay; верификация — Фаза 3.
2. **Конструкты без графа** (импортированные готовые) — рецепта нет. *Митигация:* честное пустое состояние (§9), рецепт — для собранного в BodgeGene.
3. **Дрейф версии движка** ломает хэш-совпадение. *Митигация:* пиннинг версий + warning (§7, реш. 5).
4. **Размер bundle** (вшитые большие материалы). *Митигация:* GenBank-сжатие в ZIP; content-address опционально для не-supplement сценариев.

## 14. Фазы и приёмочные критерии

| Фаза | Что | Зависит | Приёмка |
|---|---|---|---|
| **P1 — Construction record (human)** | авто-Methods (§5.3) + build-диаграмма (§5.4) из имеющихся операций/версий; панель + markdown-экспорт | — (на текущих данных) | На реальном конструкте из ≥2 операций: Methods читается корректно, диаграмма отражает граф, экспорт `METHODS.md` валиден |
| **P2 — Self-contained bundle** | `recipe.json` (§5.1) + recipe-профиль ZIP с вшитыми материалами + primers | P1 | Экспортированный `.bodge` открывается обратно; все материалы внутри (ноль внешних ссылок); product ref корректен |
| **P3 — Replay + верификация** | пере-прогон шагов → хэш-сверка → бейдж «✓/✗ шаг N» | `realiseAssembly` + `PLASMID_GIT_REVIVE` | Известный конструкт: запуск даёт идентичный продукт-хэш → ✓; подмена параметра → ✗ с указанием шага |
| **P4 — Fork (мост в автолабу)** | переменный вход → пере-прогон → вариант | P3 | Подмена одного материала → корректный вариант-продукт с провенансом |
