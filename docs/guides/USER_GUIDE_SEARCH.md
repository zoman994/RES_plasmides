## Что умеет поиск

Главная строка в верхней панели библиотеки может находить:

- молекулы и конструкты пользователя;
- проекты;
- праймеры из канонического праймерного пула;
- мотивы ДНК;
- пептиды в аннотированных белок-кодирующих областях;
- карточки рестриктаз — только по явному запросу;
- молекулы, содержащие сайты выбранной рестриктазы.

Обычный запрос не подмешивает каталог рестриктаз и каталог SnapGene. Это сделано намеренно: в повседневной работе биолог чаще ищет свою плазмиду, проект или праймер, чем справочную карточку фермента.

### Шпаргалка на одну минуту

| Я хочу | Запрос |
|---|---|
| Найти объект по названию, тегу или аннотации | `pUC19` или `glaA` |
| Найти только молекулу | `mol:pUC19` |
| Найти только праймер | `primer:T7` |
| Найти только проект | `project:Alpha` |
| Найти мотив ДНК | `seq:GAATTC` |
| Найти вырожденный мотив | `seq:GAANTC` |
| Найти пептид | `aa:HHHHHH` |
| Найти карточку EcoRI | `enz:EcoRI` |
| Найти сайты EcoRI в молекулах | `cut:EcoRI` |
| Найти кольцевые молекулы | `type:circular` |
| Найти архивные праймеры | `status:archived` |

## Обычный поиск без префикса

Запрос вроде `glaA` сравнивается без учёта регистра с:

- названием объекта;
- тегами;
- названием и типом аннотации;
- сохранёнными qualifiers аннотации, например `gene`, `product`, `locus_tag` или `EC_number`;
- известными словами, обозначающими тип или статус.

Несколько слов соединяются условием **И**. В запросе:

```text
glaA release
```

оба слова должны найтись в одном объекте, хотя они могут совпасть в разных его полях.

Описание объекта и organism уже сохраняются во внутренних данных поиска, но текущий механизм их пока не сравнивает. Поэтому не следует рассчитывать на полноценный поиск по описанию или организму.

### Когда строка автоматически считается ДНК

Один свободный токен автоматически становится ДНК-запросом, если он:

- состоит только из `A C G T U` и кодов IUPAC;
- не короче установленного порога, по умолчанию 8 нуклеотидов;
- не сопровождается другим явным биологическим режимом.

Например, `GAATTCGG` ищется и как возможный текст, и как мотив ДНК. Короткое `GAATTC` при стандартном пороге остаётся текстом. Чтобы гарантированно искать короткий мотив, используйте:

```text
seq:GAATTC
```

## Язык запросов

Префикс сообщает программе, **где** или **каким биологическим способом** искать. Регистр не важен: `SEQ:`, `seq:` и `днк:` приводятся к одному внутреннему запросу.

### Работающие префиксы

| Канонический префикс | Английские и русские алиасы | Что делает |
|---|---|---|
| `lib:` | `library:`, `библиотека:` | Ищет в обычной пользовательской библиотеке |
| `mol:` | `molecule:`, `entry:`, `construct:`, `молекула:`, `конструкт:` | Ограничивает поиск молекулами |
| `primer:` | `oligo:`, `праймер:`, `олиго:` | Ограничивает поиск праймерами |
| `project:` | `proj:`, `проект:` | Ограничивает поиск проектами |
| `seq:` | `dna:`, `nt:`, `днк:`, `посл:` | Запускает поиск ДНК |
| `aa:` | `protein:`, `prot:`, `peptide:`, `белок:`, `пептид:` | Запускает поиск пептида |
| `enz:` | `enzyme:`, `restriction:`, `фермент:`, `рестриктаза:` | Ищет карточку рестриктазы |
| `cut:` | `site:`, `digest:`, `сайт:`, `режет:`, `re:` | Ищет сайты фермента в молекулах |
| `tag:` | `тег:` | Требует совпадения с тегом |
| `type:` | `тип:` | Фильтрует по топологии или типу `primer` |
| `status:` | `статус:` | Фильтрует по статусу молекулы или праймера |

`re:` сохранён для совместимости со старыми запросами. Рекомендуемая современная форма — `cut:`.

### Распознаются, но пока не исполняются

| Префикс | Статус |
|---|---|
| `name:`, `имя:`, `название:` | Команда распознаётся, но отдельный поиск только по имени ещё не подключён |
| `feature:`, `feat:`, `annotation:`, `фича:`, `аннотация:` | Пока не исполняется как явный фильтр; обычный текст уже ищет в аннотациях |
| `in:`, `within:`, `в:` | Resolver проекта ещё не подключён |

До завершения следующих этапов используйте обычный текст, `mol:`, `primer:` или `project:` вместо этих трёх команд.

Текущий интерфейс не показывает отдельное пояснение для распознанной, но ещё не подключённой команды: она обычно выглядит как пустая выдача. Это ограничение интерфейса, а не подтверждение отсутствия объекта.

### Значения с пробелами

Фразу заключают в двойные кавычки:

```text
project:"Gla optimization"
"signal peptide"
```

Внутри значения поддерживаются экранированная кавычка `\"` и обратная косая черта `\\`. Незакрытая кавычка считается ошибкой и блокирует запуск.

Неизвестная конструкция вроде `foo:bar` не запускает скрытый режим и рассматривается как обычный буквальный текст.

### Как объединяются условия

Свободные слова и явные фильтры соединяются через **И**:

```text
seq:GAATTC status:release
cut:BsaI type:circular
tag:yeast tag:expression
```

В последнем примере объект должен иметь оба тега; совпадение значения `tag:` внутри конкретного тега выполняется как поиск подстроки.

**Текущее важное ограничение:** не используйте комбинацию свободного текста и биологического режима как строгую проверку, например `mol:pUC seq:GAATTC`. Из-за известного дефекта результат может пройти только по имени `pUC`, даже если мотив ДНК не найден. До исправления выполняйте такие проверки отдельными запросами либо обязательно смотрите, что причиной результата указана «ДНК», «белок» или «фермент».

Одновременно можно выбрать только один вычислительный режим. Запрос `enz:EcoRI seq:GAATTC` противоречив: программа не должна угадывать, нужна ли карточка фермента или поиск ДНК.

## Типы и статусы

### Типы

Рабочие значения `type:`:

- `circular`, `кольцевая`, `кольцевой`, `plasmid`, `плазмида`;
- `linear`, `линейная`, `линейный`;
- `primer`, `праймер`, `oligo`, `олиго`, `олигонуклеотид`.

Топология применима только к молекулам. Проект не является `type:project`; для него существует `project:`.

### Статусы молекул

В явном `status:` поддерживаются точные формы:

- `release`, `релиз`, `verified`, `верифицированная`, `верифицирован`;
- `wip`, `work`, `рабочая`, `рабочий`, `draft`, `черновик`;
- `deprecated`, `устаревшая`, `устаревший`, `устарел`.

### Статусы праймеров

- `imported`, `импортирован`, `импортированный`, `импорт`;
- `designed`, `спроектирован`, `дизайн`;
- `ordered`, `заказан`, `заказ`;
- `received`, `получен`;
- `archived`, `архив`, `архивная`, `архивный`, `архивирован`.

Для явного `status:` значение должно совпасть со словарём целиком. Свободное слово без префикса распознаётся шире по началу слова, но для воспроизводимого фильтра лучше использовать одну из перечисленных форм.

Модели разделены намеренно. `status:archived` возвращает архивные праймеры, а `status:deprecated` — устаревшие молекулы. Для лаборатории это разные ситуации: архивный олигонуклеотид может требовать повторного заказа, а deprecated-конструкт — отказа от использования старой версии.

Несовместимые запросы вроде `primer:T7 status:release` или `mol:pUC status:archived` блокируются, а не дают необъяснимую пустую выдачу.

## Поиск ДНК

### Короткие, вырожденные и кольцевые запросы

Полное оконное сканирование используется, если выполняется хотя бы одно условие:

- запрос не длиннее 30 нуклеотидов;
- запрос содержит неоднозначный код IUPAC;
- молекула рассматривается как кольцевая.

Этот путь умеет:

- перебирать перекрывающиеся совпадения в пределах внутренних лимитов;
- искать на обеих цепях;
- искать через origin кольцевой молекулы;
- учитывать заданное число замен;
- сопоставлять IUPAC-коды без перебора всех конкретных вариантов.

### Длинный линейный запрос

Для конкретного запроса длиннее 30 нуклеотидов на линейной молекуле используется быстрый поиск похожего участка. Он поддерживает:

- порог идентичности;
- обе цепи;
- замены;
- ограниченное восстановление однонуклеотидной вставки или делеции: максимум по одному gap с каждой стороны seed, потенциально до двух на одно совпадение.

Это не полноценное локальное выравнивание и не поиск гомологов. Алгоритм предназначен для быстрого поиска похожего участка в пользовательской библиотеке.

### Почему одна лишняя буква ломает 20-мер

Важно различать три случая:

1. **Замена**: 20 нуклеотидов остаются 20 нуклеотидами, но одна буква другая. Для короткого пути задайте `Допуск несовпадений` не меньше 1.
2. **Замена буквы на `N`**: длина не меняется. При IUPAC `авто` или `вкл` такая позиция сопоставляется по совместимости.
3. **Добавление лишней буквы**: 20 нуклеотидов превращаются в 21. Это insertion/indel, а не обычное несовпадение.

Короткий оконный поиск пока не выполняет выравнивание со вставками и делециями. Поэтому дополнительная буква в 20-мере сдвигает весь остаток запроса и может полностью убрать находку. Даже дополнительная буква `N` остаётся вставкой; IUPAC не исправляет сдвиг длины.

Это известное ограничение текущей версии, а не доказательство отсутствия исходной последовательности. Для коротких олигонуклеотидов планируется ограниченное выравнивание, учитывающее indel — вставку или делецию.

### IUPAC

Поддерживаются:

```text
R Y S W K M B D H V N
```

В коротком/IUPAC оконном поиске `U` нормализуется в `T`. В текущем поиске длинной линейной последовательности этот шаг ещё не унифицирован, поэтому в длинной строке РНК безопаснее самостоятельно заменить `U` на `T`.

Пример:

```text
seq:ACGTRNCT
```

Поиск различает:

- **идентичность** — буквы буквально одинаковы;
- **совместимость** — множества допустимых оснований пересекаются.

Поэтому `GAANTC` против `GAATTC` — совместимое совпадение, а не честные 100% буквальной идентичности. Для вырожденного запроса интерфейс показывает совместимость и отдельно число точных и неоднозначных позиций.

В текущей реализации режимы IUPAC `авто` и `вкл` практически эквивалентны. `выкл` делает неоднозначные символы буквальными: `N` в запросе совпадает только с буквальным `N` в последовательности.

### Обе цепи

По умолчанию проверяются прямая и обратная комплементарная цепи. В оконном режиме палиндромный мотив в одной и той же позиции показывается как одно совпадение на обеих цепях; длинный линейный путь может вернуть отдельные результаты `+` и `−`.

### Кольцевой поиск

- `авто` — переход через origin разрешён только для молекул, помеченных как кольцевые;
- `вкл` — все молекулы временно рассматриваются как кольцевые;
- `выкл` — совпадение не может пересекать origin.

Биологический смысл прост: точка начала отображения плазмиды не разрывает физическую кольцевую ДНК.

## Поиск белка

Запрос `aa:` ищет пептид не в сырой строке ДНК, а в белках, выведенных из аннотированных областей типов:

- `CDS`;
- `gene`;
- `marker`;
- `reporter`.

Минимальная длина — 3 аминокислоты. Поиск точный; `X` означает любой аминокислотный остаток.

### Как строится белок

Для каждой подходящей аннотации программа:

1. находит связанные интроны;
2. исключает их из зрелой кодирующей последовательности;
3. учитывает направление цепи;
4. выбирает рамку по `/codon_start`, сохранённой рамке или эвристике;
5. транслирует последовательность до первого стоп-кодона;
6. ищет пептид;
7. возвращает совпадение на реальные нуклеотидные координаты экзонов.

Поэтому `aa:HHHHHH` может найти His-tag независимо от использования кодонов `CAT` или `CAC`, на обратной цепи и через корректно аннотированный интрон.

В выдаче могут показываться название CDS, цепь, аминокислотный диапазон, рамка, число экзонов и отметка «интрон исключён».

### `X` и честная метрика

Для `aa:HXHH` три буквы совпадают буквально, а `X` совместим с любым остатком. Результат может иметь 75% буквального совпадения и 100% совместимости. `X` не должен искусственно превращать метрику в «100% идентичность».

### Ограничения белкового поиска

Текущий поиск:

- не выполняет шестира́мочную трансляцию всей плазмиды;
- не ищет неаннотированные ORF;
- не использует BLOSUM и не ищет похожие, но отличающиеся пептиды;
- не предсказывает интроны во время поиска;
- не моделирует отдельные транскрипты и альтернативные изоформы;
- не гарантирует корректную обработку compound CDS, пересекающей origin;
- фактически использует стандартную таблицу генетического кода 1.

Если интроны корректно связаны с CDS через `regionId` или `parentId`, они исключаются правильно. Но несколько альтернативных интронов одной области сейчас могут быть объединены в одну искусственную модель зрелой мРНК. Это особенно важно для сложных объектов вроде `Gla`: найденный пептид следует проверять против конкретной изоформы.

Номер `/transl_table`, отличного от 1, показывается в пояснении результата как `код N`. Это не означает, что указанная таблица была применена: фактическая трансляция всё ещё использует таблицу 1. Для митохондриальных и других нестандартных кодов возможны ложные находки и пропуски.

## Рестриктазы: карточка и сайты — разные действия

### Найти фермент

```text
enz:EcoRI
```

Запрос ищет справочную карточку по имени, сайту узнавания или overhang. Карточки каталога добавляются в поисковый набор только для валидного `enz:` и не участвуют в обычной выдаче.

Клик по результату открывает небольшую карточку. Сам клик не запускает сканирование молекул.

### Найти сайты фермента

```text
cut:EcoRI
```

или старый эквивалент:

```text
re:EcoRI
```

Запрос возвращает пользовательские молекулы и координаты участков узнавания. В карточке фермента для этого есть отдельная кнопка **«Найти сайты в библиотеке»**.

`cut:` поддерживает классические Type II, добавленные пользователем ферменты и Type IIS по каноническому имени, например `cut:BsaI`. Для Type IIS подсвечивается последовательность узнавания, а не вынесенная за её пределы физическая точка разреза.

### Что `cut:` не доказывает

Наличие мотива узнавания не равно гарантированному рестрикционному гидролизу. Поиск не моделирует:

- метилирование;
- star activity;
- буфер и температуру;
- кинетику и эффективность гидролиза;
- доступность участка ДНК;
- размеры и состав продуктов рестрикционного гидролиза.

### Текущие ограничения каталога

- `enz:` сейчас строится из классического каталога и добавленных пользователем ферментов;
- Type IIS из Golden Gate ещё не объединены с карточками `enz:`;
- алиасы `BbsI → BpiI`, `Eco31I → BsaI`, `Esp3I → BsmBI` относятся к следующему этапу;
- неизвестный или неоднозначный `cut:` пока может дать пустую выдачу вместо будущего списка кандидатов.

## Как читать выдачу

В зависимости от причины совпадения строка результата может содержать:

- иконку типа сущности;
- название; подсветка появляется, только если совпало само название;
- причину совпадения: тег, аннотация, тип, статус, ДНК, белок или фермент;
- биологическую метрику для ДНК, белка или сайта;
- число локализаций для координатного биологического совпадения.

Один объект показывается один раз, даже если в нём найдено много участков. В строке хранится до 50 локализаций на объект. Общий лимит выдачи по умолчанию — 200 объектов.

Ранжирование обычного запроса отдаёт приоритет названию, затем биологическому совпадению, тегу, аннотации, типу и статусу. При явном `seq:`, `aa:` или `cut:` биологическое совпадение поднимается выше совпадения имени.

### Что происходит по клику

- молекула — открывается инспектор и выполняется переход к лучшему участку;
- проект — становится активным;
- праймер — открывается праймерный пул, строка выделяется и прокручивается в видимую область;
- праймер в старом формате — сначала переносится в канонический пул с сохранением всех полей, поддерживаемых канонической моделью;
- фермент — открывается карточка фермента.

Если переход к молекуле может затронуть несохранённую работу, сначала применяется стандартная защита от потери изменений.

## Настройки поиска

Ссылка **«изменить»** находится в заголовке открытой выдачи рядом с кратким описанием порога и цепей.

| Настройка | Значение по умолчанию | Что реально меняет |
|---|---:|---|
| Порог сходства | 80% | Длинный конкретный линейный ДНК-поиск |
| Обе цепи | Включено | ДНК-поиск; `cut:` независимо проверяет обе цепи |
| Неоднозначные коды IUPAC | Авто | `авто/вкл` используют совместимость, `выкл` — буквальное сравнение |
| Кольцевой поиск | Авто | Переход через origin для `seq:` и `cut:` |
| Минимальная длина ДНК-запроса | 8 | Только автоматическое распознавание; явный `seq:` обходит порог |
| Допуск несовпадений | 0 | Замены в коротком/IUPAC/circular оконном поиске, но не indel |
| Только последние версии | В разработке | Пока не влияет на выдачу |
| Максимум результатов | 200 | Общий предел, допустимый диапазон 10–1000 |

`Порог сходства` и `Допуск несовпадений` не действуют одновременно на каждый запрос. Первый относится к длинному линейному поиску, второй — к короткому оконному поиску. Это особенно важно при интерпретации коротких олигонуклеотидов.

Настройки сохраняются локально. Повреждённые, устаревшие или выходящие за разрешённый диапазон значения автоматически заменяются безопасными.

## Сообщения и ошибки

### «Ничего не найдено»

Запрос выполнен, но совпадений в выбранной области и в рамках текущего алгоритма нет. Это не универсальное доказательство биологического отсутствия: учитывайте аннотации, настройки, indel и ограничения изоформ.

### «Поиск по последовательности не выполнен; показаны только результаты по метаданным»

Последовательностный движок не завершил поиск или превысил тайм-аут. Нельзя заключать, что последовательности нет: повторите запрос. Если запрос содержал независимые текстовые условия, их результаты могут остаться доступны; для чистого `seq:` список обычно будет пуст.

### «Противоречивый запрос — поиск не выполнен»

Вычисление вообще не запускалось. Частые причины:

- два разных режима: `enz:EcoRI seq:GAATTC`;
- повтор одного режима, например два `seq:`;
- два ограничения области, например `mol:` и `primer:`;
- пустой `seq:`, `aa:`, `enz:` или `cut:`;
- недопустимая ДНК, например `seq:amp`;
- незакрытая кавычка;
- несовместимые область, вид поиска или статус.

Сейчас верхняя строка показывает общее сообщение. Подробная inline-диагностика планируется вместе с новым UI поиска.

### Быстрая смена запроса

Предыдущий расчёт отменяется и его поздний результат не отображается. Это штатное поведение, а не ошибка.

---

## Быстрый фильтр дерева

Поле дерева — облегчённый фильтр только по текстовым данным. Оно не запускает фоновый поиск ДНК, белковый поиск или поиск сайтов.

Явный `seq:`, `aa:`, `enz:`, `cut:` и пока неисполняемые префиксы полей не должны превращаться в совпадение со всей библиотекой. Дерево не показывает ложных совпадений, выдаёт пустой локальный результат и предлагает **«Открыть полный поиск»**.

В текущей версии дерево и верхняя строка ещё используют одно значение запроса. Их независимые состояния запланированы вместе с новым интерфейсом поиска.

---

## Другие поисковые поля пока не полностью унифицированы

До завершения запланированной унификации разные поверхности могут вести себя по-разному:

- выбор молекулы в Canvas/Assembly/Align использует более простой буквальный DNA-путь;
- локальный поиск внутри открытой последовательности имеет собственные правила и пока отвергает IUPAC;
- праймерный пул ещё не получил отдельную текстовую строку поиска;
- локальные выборщики рестриктаз пока используют собственные правила ранжирования и разрешения имён;
- `primer:T7` ищет запись праймера, а не проверяет его посадку.

Поиск карточки праймера и проверка его посадки принципиально разделены. Наличие праймера в пуле не доказывает его пригодность: для этого нужны отдельные расчёты 3′-комплементарности, Tm, хвоста, специфичности и возможных ампликонов.

## Что запланировано

Запланирован визуальный выбор режима и фильтров:

```text
[Библиотека ▾] [строка поиска] [+ Фильтр]
```

Пользователь сможет выбирать «Молекулы», «Праймеры», «Проекты», «ДНК», «Белок», «Сайты» или «Рестриктазы» из списка, не запоминая префиксы. Выбор мышью и ручной префикс будут создавать один и тот же `QueryPlan`.

Также запланированы removable chips, подсказки по режиму, конкретные сообщения об ошибках, полноценная клавиатурная навигация, IME-safe ввод и независимые состояния дерева и полного поиска.

Пока новый интерфейс не завершён, режим выбирается ручным префиксом. Будущий выпадающий выбор не описывается здесь как уже готовая функция.

## Практические лабораторные сценарии

### Найти короткий EcoRI-мотив как ДНК

```text
seq:GAATTC
```

Явный префикс нужен, потому что шесть нуклеотидов короче стандартного порога автоопределения.

### Найти сайты EcoRI в плазмидах

```text
cut:EcoRI
```

Вы увидите молекулы и позиции мотивов. Для планирования рестрикционного гидролиза отдельно проверьте число сайтов, буфер, температуру, метилирование и ожидаемые фрагменты.

### Найти вырожденный мотив

```text
seq:ACGTRNCT
```

Это поиск по IUPAC-совместимости. Заменить неизвестную позицию на `N` можно; вставлять дополнительный `N` нельзя считать заменой — это indel.

### Найти His-tag независимо от оптимизации кодонов

```text
aa:HHHHHH
```

Поиск сработает на `CAT`- и `CAC`-кодонах, если область аннотирована как транслируемая и правильно задана рамка/сплайсинг.

### Найти архивный праймер

```text
status:archived
```

Запрос ограничивает область праймерами и не смешивает их с deprecated-молекулами.

### Найти запись праймера T7

```text
primer:T7
```

После открытия праймера его фактическую посадку на целевую молекулу следует проверять отдельным инструментом.
