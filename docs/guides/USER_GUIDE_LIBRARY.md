# Пользовательский гайд — Library

> Как пользоваться окном Library в BodgeGene. Для биолога-пользователя, не для разработчика.

---

## Что такое Library

Library — главное окно BodgeGene. Это твоё рабочее пространство со всеми плазмидами, праймерами и проектами. Когда ты открываешь приложение — ты попадаешь в Library.

В Library три раздела (зоны), каждый со своими правилами. Это не три разных вкладки — все три видно одновременно в дереве слева.

---

## Три зоны

### `⚐ Без проекта` — свободная зона

Сюда складывай плазмиды и фрагменты, которые не привязаны ни к одному проекту. Это твой личный архив, аналог папки `~/Documents/SnapGene Files/`.

**Что можно делать:**
- Создавать папки и подпапки (правый клик → «Новая папка»).
- Перетаскивать плазмиды между папками.
- Переименовывать (двойной клик).
- Удалять.
- Перетаскивать плазмиду в активный проект → в проект попадёт **копия**, оригинал останется здесь.

**Что нельзя:**
- Редактировать саму последовательность напрямую — она «заморожена» в этой зоне. Если нужно что-то поменять — выбери плазмиду и нажми `Manual-edit ветка` в Inspector справа. Это создаст редактируемую копию, оригинал останется нетронутым.

### `📦 ProjectName.bodge` — твои проекты

Каждый твой `.bodge` файл (проект) появляется в дереве как папка. Внутри у неё прибитая структура из трёх подразделов:

- **🔀 DAG** — граф операций проекта. Клик открывает полноэкранный DAG-вид.
- **📥 Контейнеры** — плоский список молекул которые ты *притащил* в проект (импортировал, добавил из библиотеки, и т.п.). Результаты PCR/Gibson сюда **не попадают** — они только в DAG. Это даёт чёткую границу «что я положил vs что у меня в результате получилось».
- **🧬 Праймеры** — плоский список праймеров проекта.

Эта структура **прибитая** — нельзя добавить дополнительные подпапки внутри `.bodge`.

#### Активный проект

Один из проектов помечен `[active]` — это тот, в котором ты сейчас работаешь. В его `.bodge` папке ты можешь:

- Открыть Container Window для любого контейнера (двойной клик).
- Извлечь контейнер в свободную зону (`⊳` action в Inspector).
- Удалить контейнер из проекта.
- Добавить новый контейнер через `+ Добавить`.

#### Импортированный (не активный) проект

Если ты импортировал чужой `.bodge` либо открыл свой старый — он появляется как `📦 ProjectName.bodge 🔒 read-only`. Внутри:

- Можешь **смотреть** DAG, контейнеры, праймеры.
- Можешь **скопировать** контейнер в свой активный проект (`🔗 cross-project clone`) — создаётся новая копия, оригинал в чужом проекте не трогается.
- Можешь **открыть как активный** — текущий активный закроется (если есть несохранённые изменения — спросит подтверждение), новый станет активным.
- Не можешь редактировать.

### `🧬 Лабораторный пул`

Это **общий** раздел primer'ов для всех твоих проектов. Сюда складывай праймеры которые физически есть у тебя в морозильнике.

Две подсекции:

- **❄️ В лаборатории** — праймеры с флагом «у меня есть в трубке». Их видно с `❄️` иконкой.
- **📚 Из чужих проектов** — праймеры которые ты **видел** в импортированных `.bodge`, но физически у тебя их нет. Если ты потом найдёшь / закажешь такой primer — нажми action «Промотить в лабораторию», он переедет в `❄️ В лаборатории`.

Праймеры в Lab pool — общий ресурс, не дубликаты. Один и тот же primer виден и в проектной папке (где он используется в реакции), и в Lab pool (где он лежит в морозильнике). Counter `used in 8 проектах` показывает в скольких твоих проектах primer применяется.

## Как добавить плазмиду / primer

В верхнем левом углу Tree панели — кнопка **`+ Добавить`** (амбер). Нажимаешь → открывается окно с четырьмя вариантами:

| Источник | Когда использовать |
|----------|---------------------|
| **📁 Файл** | Импортируй `.bodge` / `.gb` / `.dna` / `.fasta` файл с диска (drag-drop тоже работает) |
| **📋 Вставить последовательность** | Скопировал последовательность из статьи / письма — вставляешь в textarea, BodgeGene определит формат |
| **📚 Каталог** | Берёшь известную плазмиду из BodgeGene catalog (curated 7 категорий) либо SnapGene catalog (19 категорий, 2800+ плазмид) |
| **🔗 Из другого `.bodge`** | Копируешь конкретный контейнер из чужого проекта без импорта проекта целиком *(будет в M-X.9, пока заблокировано)* |

После выбора источника спрашивается **куда положить**:

- **В активный проект** (`📥 Контейнеры` твоего `.bodge`) — default если у тебя открыт проект.
- **В свободную зону** (`⚐ Без проекта`) — default для каталога, либо если активного проекта нет.
- **В лабораторный пул** — только для primer'ов.

Default зависит от источника, но ты всегда можешь изменить.

После «Далее» — стандартный preview wizard где можно переименовать, выбрать аннотации, и т.п. Это тот же wizard что в Importer'е v0.8.0.

## Что я вижу когда выбираю плазмиду

Справа от дерева — Inspector. У него четыре вкладки:

### Обзор (default)

То что ты видишь когда первый раз кликаешь на плазмиду. Содержит:

- **Контекст-баннер** сверху — правило-в-одну-строку для этой зоны:
  - «⚐ Без проекта · свободная зона · sequence frozen»
  - «📦 Активный проект · изменения сохраняются в `<name>.bodge`»
  - «🔒 Read-only · импортированный проект · `<name>.bodge`»
  - «🧬 Лабораторный пул · primer в морозильнике»
- **Происхождение (lineage trail)** — цепочка «откуда эта плазмида у меня». Например:
  - Этот контейнер
  - ↑ склонирован из Library / ChitinaseExpr / pET28b-Chit (06.05.2026)
  - ↑ склонирован из catalog Demo / pET28b (загружен 28.04.2026)
  
  Биолог видит происхождение в один взгляд. Кликабельно — переход к источнику если он ещё доступен.
- **Превью** — мини-карта плазмиды (PlasmidMiniMap).
- **Метаданные** — origin, source, agent, добавлен, tags, topology.
- **Действия** — кнопки актуальные для текущей зоны (см. ниже).

### Последовательность (с counter `7382`)

Двуцепочечная последовательность + AA-translation strip + аннотации цветовым фоном. То же что в Importer'е, но **только для просмотра**.

Сверху таба inline-баннер: «🔒 Просмотр read-only. Edit последовательности — в Container Window». Кликабельная ссылка ведёт в Container Window.

Каретку ставить можно, выделять диапазон можно (для копирования). Редактировать — нет.

### Аннотации (с counter `14`)

Linear feature view + region list справа. Filter chips сверху (`все / CDS / primer`). То же что в Importer'е, **только для просмотра**.

Edit аннотаций (создать новую, удалить, переименовать) — через Container Window либо через PreImport flow когда импортируешь файл заново.

### История (counter `3`, скрыта если коммитов нет)

Список коммитов внутри контейнера: ручные правки + DAG-операции. Каждый коммит с цветным badge по типу:
- Амбер — Manual edit (правил руками)
- Зелёный — Gibson assembly / другая биологическая операция
- Серый — Initial import (origin)

В каждом коммите видно когда, кто, что изменилось, с человеческим описанием («Заменил 3 nt в позиции 142–145 — устранён внутренний BsaI сайт»). Для biological op — cross-link на DAG-узел проекта.

**В версии M-X.7a содержимое таба = placeholder.** Counter работает (показывает количество), но при клике видно «Список коммитов и version-actions — M-X.7b». Полная функциональность придёт в следующей итерации когда зафиксируется модель версионирования.

## Действия в Inspector — что и где

Кнопки внизу Inspector меняются в зависимости от того **где** выбранный item:

### В свободной зоне `⚐`
- **Использовать в активном** *(primary, амбер)* — копирует в активный проект.
- Открыть — двойной клик аналог.
- Manual-edit ветка *(disabled в M-X.7a)* — создаст редактируемую копию.
- Переместить — выбрать другую папку.
- Экспорт — скачать `.gb` файл.
- Удалить *(красное)*.

### В активном `.bodge`
- **Container Window** *(primary)* — открыть полноэкранный редактор.
- Использовать в DAG — добавить как input в новую DAG-операцию.
- Извлечь в Loose — копия в свободную зону.
- Сохранить как версию *(disabled в M-X.7a)*.
- Удалить из проекта *(красное)*.

### В read-only `.bodge`
- **Скопировать в активный** *(primary)* — cross-project clone.
- Скопировать в Loose.
- Открыть как активный проект *(в разработке)*.
- Просмотр.

### Primer в Lab pool
- **Использовать в проекте** *(primary)* — открывает Primer Wizard.
- Редактировать заметки.
- Снять метку «в лаборатории» либо «Промотить в лабораторию» (depends on текущего состояния).
- Удалить *(красное)*.

## Когда нужен Container Window

Library Inspector — это **просмотровый** интерфейс. Любые правки последовательности и аннотаций идут через Container Window:

- Двойной клик на контейнер в дереве → Container Window.
- Либо action `Container Window` в Inspector action-row.

Container Window открывается полноэкранно. В нём ты редактируешь последовательность, добавляешь / удаляешь / переименовываешь аннотации, делаешь modify-ends, и т.п. Когда закрываешь Container Window — изменения автоматически сохраняются в `.bodge` файл активного проекта (либо требуют explicit сохранения в свободной зоне через Manual-edit ветку).

DAG операции (PCR / Gibson / Golden Gate / digest) — отдельный flow через DAG view (`🔀 DAG` в дереве либо в top bar breadcrumb).

## Drag-and-drop — как двигать вещи

| Что перетаскиваешь | Куда | Что произойдёт |
|---------------------|------|----------------|
| Контейнер в Loose | в Loose-папку | move (переезжает) |
| Контейнер в Loose | в активный `.bodge` | clone (копия в проекте) |
| Контейнер из активного `.bodge` | в Loose | copy-out (копия в свободной зоне) |
| Контейнер из read-only `.bodge` | куда угодно | заблокировано (cursor `not-allowed`) |
| Primer | в Lab pool «В лаборатории» | promote (флаг `inLabStock=true`) |
| Primer из Lab pool | куда угодно вне lab pool | заблокировано |

При drag над целью cursor меняется (`move` / `copy` / `not-allowed`) — так ты видишь что произойдёт до того как отпустишь.

## Поиск

Два уровня:
- **App-level** в top bar (`Поиск ⌘K`) — глобальный поиск + быстрые actions с filters (`>5kb`, `CDS`). *Полная функциональность в M-X.7c, в M-X.7a — простой text-фильтр.*
- **Tree-level** под кнопкой `+ Добавить` (`Фильтр в дереве…`) — простой text-search по имени item'а.
