# Форматы файлов BodgeGene

## Главное правило

Для наиболее полного текущего экспорта проекта используйте **`.bodge`**. Формат ещё находится в development/pre-freeze состоянии: после экспорта обязательно проверьте повторное открытие. Для обмена отдельной последовательностью с другими программами используйте **GenBank** или **FASTA**.

Формата `.bodgebox` в текущем приложении нет.

## `.bodge` — текущий проектный контейнер

`.bodge` — ZIP-контейнер BodgeGene с manifest и разделами проекта. Текущий writer создаёт development-версию BODGE v2 (`fileFormatVersion: 2.0.0`). Reader различает v1 и v2, но до format freeze экспорт нельзя считать гарантированно без потерь.

Архив может содержать:

```text
manifest.json
project.json
README.md
containers/<id>.gb
assemblies/<id>.json
primers/pool.json
library/entries.json
notebook/entries.json
notebook/attachments/...
refs/external.json
extensions/<vendor>/...
```

Конкретный набор разделов зависит от данных проекта и выбранного профиля экспорта. Отсутствующий необязательный раздел не означает повреждение архива.

### Что текущий экспорт стремится сохранить

- молекулы и их аннотации;
- сборки и их состояние;
- пул праймеров;
- библиотечные записи проекта;
- записи Notebook и доступные вложения;
- внешние ссылки и зарегистрированные extensions.

Не редактируйте содержимое `.bodge` вручную: manifest содержит сведения о файлах и контрольные суммы. Для диагностики архив можно открыть как ZIP-копию, но изменённый вручную архив не следует считать корректным проектом.

Технический контракт формата: [SPEC_BODGE_FORMAT_V2_CORE.md](../specs/SPEC_BODGE_FORMAT_V2_CORE.md).

## Импорт последовательностей

Поддерживаемые входные форматы:

| Формат | Расширения | Что импортируется |
|---|---|---|
| GenBank | `.gb`, `.gbk`, `.genbank` | последовательность, топология и поддерживаемые features/qualifiers |
| FASTA | `.fasta`, `.fa`, `.fna` | последовательность и доступное имя/описание |
| SnapGene | `.dna` | последовательность и поддерживаемые метаданные через локальный backend |
| Текст | GenBank, FASTA или буквы последовательности | данные, распознанные по содержимому |

Для `.dna` нужен запущенный Python-backend. Текстовые GenBank/FASTA-файлы ограничены защитным лимитом размера; текущий импорт отклоняет файлы больше 25 МБ.

После импорта обязательно проверьте:

1. длину и топологию;
2. начало координат кольцевой молекулы;
3. strand и границы ключевых аннотаций;
4. праймеры и связанные с ними последовательности;
5. предупреждения импортера.

## Экспорт для других программ

### Одна молекула

Действие **«Экспортировать .gb»** создаёт GenBank-файл отдельной библиотечной молекулы. Его можно открыть в программах, поддерживающих GenBank.

### Молекулы проекта

Действие выгрузки проекта из дерева библиотеки создаёт ZIP с отдельными `.gb` файлами. Это пакет последовательностей, а не полный проект BodgeGene.

### Проект BodgeGene

Экспорт приложения в `.bodge` является наиболее полным текущим способом переноса структуры BodgeGene. До закрытия известных format-v2 разрывов он не заменяет проверенную резервную копию: экспортируйте, повторно откройте файл и сверьте ключевые молекулы, сборки, праймеры и Notebook.

## Что может потеряться при обмене

GenBank — плоский формат features. Он не выражает всю модель BodgeGene: сборки, Notebook, историю рабочего состояния и часть иерархических связей аннотаций.

Поэтому:

- не ожидайте byte-for-byte round-trip через SnapGene, ApE, Geneious или другой редактор;
- неизвестные qualifiers могут быть сохранены, изменены или удалены внешней программой;
- после внешнего редактирования импортируйте результат как данные, требующие повторной проверки;
- не считайте COMMENT или custom qualifiers доказательством того, что последовательность не менялась.

Чтобы снизить риск потерь, храните проверенный `.bodge` рядом с обменным GenBank-файлом и не удаляйте исходные данные до успешного повторного открытия.

## Резервное копирование

Перед миграцией формата, крупным редактированием или очисткой библиотеки:

1. экспортируйте проект в `.bodge`;
2. сохраните файл вне рабочего каталога приложения;
3. проверьте, что файл снова открывается;
4. только после этого удаляйте исходные данные.
