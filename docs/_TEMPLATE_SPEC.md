## 0.1. Visual reference / Source of truth

Заполняется когда есть HTML mockup / wireframe / screenshot / design asset. Если нет — пишется в одну строку (см. ниже).

**Mockup file:** `docs/design_assets/&lt;file&gt;.html` (либо ссылка на screenshot / Figma).

**Mockup audit (Chat обязан сделать до написания спеки):**
- Открыть mockup в Chrome.
- Пройтись по DOM/CSS на структуру: panels, components, text styles, colors, spacing.
- Зафиксировать ключевые design tokens которые используются: список `var(--token)` встречающихся в styles.

**Acceptance rule (mandatory phrasing):**
> «Всё что есть в mockup'е = приёмочный критерий. Что НЕ в mockup'е (hover/focus polish behind state, prefers-reduced-motion, и т.п. тонкости) = polish, можно отложить, но Code в финальном отчёте перечислит unmet items с flag для Chat — приёмочный критерий или реальный polish?»

**Если mockup'а нет** — заменить эту секцию одной строкой:
> «No visual reference, design — на усмотрение Code в рамках `docs/DESIGN_SYSTEM.md` tokens.»

Пропускать §0.1 нельзя — должна быть либо явная ссылка на mockup, либо явная строка «no visual reference». M-X.7a drift (35 расхождений) — root cause был в отсутствии этой секции.

## 0.2. Component reuse audit

Перед написанием задач — Chat grep'ит по `gui/designer/src/components/` на каждый существующий компонент в скоупе. Цель — поймать legacy hangovers до того как Code возьмёт «первый под руку» легаси.

**Audit checklist:**
- [ ] Для каждого компонента-кандидата проверены имена-собратья: `*View`, `*Editor`, `*Pane`, `*Workspace`, `Mini*`, `*v2`, папки `/index.jsx` vs одиночные `.jsx` в корне `components/`.
- [ ] Если есть rewrite/современная версия — проверено что она использовалась в недавних спринтах (M-B+, M-C+, M-X.x).
- [ ] Legacy alternatives явно перечислены как «NOT use».

**Use / NOT use table:**

| Use | NOT use (legacy) | Reason |
|-----|------------------|--------|
| `components/SequenceView/index.jsx` (M-B.3 rewrite, track-based) | `components/SequenceMapView.jsx` (superseded by M-B.3 rewrite) | DEC-SQV-07: plain fragments shape, NO container imports — для read-only Inspector |
| `components/Annotator/PreviewTab.jsx` pattern (M-X.3 canonical) | inline `AnnotationEditor` в новых компонентах (superseded by M-X.3 Annotator) | annotations встроены в SequenceView через AnnotationTrack |

Если все компоненты в скоупе — новые (нет existing equivalents) — заменить таблицу на «Все компоненты в скоупе — новые. No legacy concerns.»

**Терминология.** Не путать **superseded UI** (старые UI-компоненты после rewrite) и **v0.5 legacy codebase** (алгоритмические модули — primer-design, mutagenesis, restriction-db, snapgene_parser — переиспользуются в v0.6+ по ARCHITECTURE_v2 §8 + DEC-V2-08). Audit — только про первое.

**Rationale:** root cause M-X.7a K3 — Code импортировал superseded `SequenceMapView`+`AnnotationEditor` при наличии современных `SequenceView`+`Annotator/PreviewTab`. Спека не указывала «use X NOT Y» → Code пошёл по пути наименьшего сопротивления. Эта секция закрывает класс антипаттерна.

## 3. Scope

### IN

- `path/to/file.jsx` — что именно меняется.
- `path/to/helper.js` — что меняется.
- новый файл `path/to/new-helper.js` — зачем.

### OUT (явно отложено)

- Фича / рефакторинг — почему не сейчас (Sprint N, v1.1, и т.п.).
- V_X, V_Y — остаются OPEN до отдельного спринта.
- Всё, что не в IN, **не трогаем**. Даже если «очевидно улучшает».

Если было §0.5 — границы IN/OUT опираются на ответы Игоря о scope, ссылаться на конкретные Q/A.

## 5. Предположения

**Критический раздел.** Ловит класс ошибок «а я думал, что &lt;входные данные всегда такие&gt;» (сегодняшний пример: «все annotations имеют id» оказалось ложным на whole-plasmid-import, root cause 2 FAIL приёмок).

**Важно:** если было §0.5 kickoff-интервью, факты из него — **факты**, не assumption'ы. В §5 сюда не дублируются. Здесь остаётся только то, что Игорь **не затронул** в интервью: инварианты существующего кода, состояние смежных модулей, поведение библиотек. Для хорошей спеки после интервью §5 = 1–3 пункта, не 5.

1–5 bullet'ов формата:

- **&lt;Предположение&gt;.** Источник: откуда знаю (код / приёмка / договорённость / тест). Проверено: да / нет / частично.

Для непроверенных — **одно из двух**:
- Первый K-шаг = «проверить &lt;предположение&gt;», потом только основная логика.
- Явная строка в CURRENT_TASK.md: «перед началом проверить &lt;предположение&gt;».

**Примеры:**

- **Все annotations в store имеют `id: string`.** Источник: AnnotationEditor через UI ставит uuid. Проверено: **нет** — whole-plasmid-import идёт мимо AnnotationEditor. **Действие:** первый K-шаг — нормализация `id` в read-path `getRegions`.
- **`fragment.topology` persisted на всех сохранённых проектах.** Источник: Sprint 1.7 K12 добавил поле + migration. Проверено: да, Vitest в fragment-slice.test.js.
- **Новая палитра `feature-palette.js` покрывает все 15 типов annotations.** Источник: K2 Map-WS-1-fix прошёл приёмку D2 PASS. Проверено: да, визуально.

Не писать «нет предположений» ради галочки. Если реально нет — перечислить 2–3 явных инварианта, на которые опираешься (например, «Zustand store синхронный», «fragments и annotations никогда не перезаписываются без migration»).

## 8. STOP-условие и формат отчёта

### STOP

После commit K&lt;last&gt; Code останавливается. **НЕ:**

- обновляет `PROJECT_STATE.md` / `RELEASES.md` / `DECISIONS.md` / `ANCHORS.md` / `BUGS.md` (это делает Chat в сессии приёмки);
- перемещает спеки в `docs/archive/`;
- начинает следующий спринт;
- трогает OPEN баги не из этого скоупа.

### Формат отчёта

Code дописывает в конец `CURRENT_TASK.md` блок:

```
## Отчёт Code по Sprint <ID>

- K1 коммит: `<hash>` — <commit message>
- K2 коммит: `<hash>` — <commit message>
- ...
- Изменения размеров:
  - file.jsx — X KB → Y KB (ΔZ KB; hard 40 — OK/WARN/FAIL)
- Новые файлы: `path/new.js` (X KB), `__tests__/new.test.js` (+N тестов)
- Vitest: N/N (baseline M, ожидание M + ΔN)
- pytest: N/N (не трогалось | +K)
- vite build: clean | warnings: <...> | errors: <...>
- Отклонения от спеки (§3 / §4 / §6): <явный список или «нет»>
- Противоречия с §0.5 (если обнаружены): <список или «нет»>
- Size budget: OK | нарушители <...>
```

Если отчёта нет — Chat не финализирует приёмку, просит отчёт.
