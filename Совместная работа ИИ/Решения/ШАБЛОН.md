# DISP-<SOURCE-ID>-NNN — Короткое решение

> **NON-CANONICAL PROVENANCE — DOES NOT AUTHORIZE CODE**

- Decision ID: `DISP-<SOURCE-ID>-NNN`.
- Ведущий Ревизор / экземпляр:
- Дата / часовой пояс:
- Decision class: `INPUT_TRIAGE` / `PACKAGE_REVIEW`.
- Disposition: одно значение из vocabulary выбранного class.
- Source ID:
- Source path: точный путь.
- Source SHA-256: полный SHA-256.
- Supersedes decision ID: `NONE` для первого решения либо ID непосредственного predecessor.
- Supersedes decision path: `NONE` либо точный путь непосредственного predecessor.
- Supersedes decision SHA-256: `NONE` либо полный SHA-256 непосредственного predecessor.
- Reason:
- Canonical target: `path + stable locator` либо `NONE`.

## Vocabulary

- `INPUT_TRIAGE`: `ACCEPT FOR TRIAGE`, `CLARIFY`, `PARK`, `REJECT`.
- `PACKAGE_REVIEW`: `ACCEPT`, `CORRECTION`, `REJECT`, `STOP`.
- `PENDING` не является disposition: оно означает отсутствие decision-файла.

## Инварианты заполнения

- `ACCEPT FOR TRIAGE` создаётся только после переноса source ровно в один primary
  tracker: дефект — `BUGS.md`, улучшение/долг — `docs/BACKLOG.md`; `Canonical target`
  содержит его stable locator.
- `PARK` требует stable locator в `docs/BACKLOG.md`. `CLARIFY`, `PARK` и `REJECT` не
  авторизуют Кодера.
- `CORRECTION` может поддержать ровно один correction manifest. `ACCEPT` закрывает
  package; `REJECT` и `STOP` запрещают изменения отклонённого candidate.
- Для первого решения NNN = `001`, а все три `Supersedes decision` = `NONE`.
- Successor сохраняет тот же source ID/path/SHA-256, получает
  `max(existing NNN for source)+1` и пинит непосредственного predecessor во всех трёх
  `Supersedes decision` полях. Collision имени или два successors одного predecessor —
  `STOP`; выбирать решение по самой поздней дате нельзя.
- Source, predecessor и этот DISP после handoff не изменяются и не получают backlink.
  Уточнение решения создаётся новым successor-файлом.
- SHA-256 этого DISP не записывается внутрь файла. После freeze его фиксирует внешний
  handoff или `CURRENT_TASK.md`.
- Этот файл доказывает решение Ревизора, но не даёт writable scope. Запись разрешает
  только отдельный `CURRENT_TASK.md` с base, IN/OUT и manifest.
